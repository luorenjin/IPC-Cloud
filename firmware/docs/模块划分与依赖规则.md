## 1. 目录与层次

```
firmware/
├── hal/                 L1  接口头文件 + hal.c（版本校验/聚合），无平台代码
├── core/                L2  核心服务（实现待下一步）
│   └── include/core/    frame_bus.h event_bus.h config.h log.h profile.h module.h
├── modules/             L3  功能模块（实现待下一步）
│   ├── idp/ rtsp/ onvif/ gb28181/ recorder/ ota/ console/ ivs/ snapshot/
├── profiles/            L4  能力清单 schema 与各型号 JSON
├── platform/            L0  平台实现：mock/（x86）；gk7205v200/ 等待硬件定后加入
├── tests/               HAL 一致性测试、模块单测
└── docs/
```

依赖方向（只允许向下）：`profiles → modules → core → hal ← platform`。

## 2. 硬性规则（代码评审门禁）

| # | 规则 | 检查方式 |
|---|---|---|
| R1 | `core/`、`modules/` 禁止 `#include` 任何 `platform/` 下头文件 | CI grep |
| R2 | `core/`、`modules/` 禁止 `#ifdef`/`#if` 出现 `PLATFORM_`、`GK7205`、`RV1106`、`HI35` 等平台宏 | CI grep |
| R3 | 业务层不得硬编码型号/传感器/引脚；一律从 `profile_get()` 或 `cfg_get_*` 取 | 评审 |
| R4 | 模块间不得直接调用对方函数；通过 `event_bus` 与 `config` 交互 | 评审 + 链接符号检查 |
| R5 | 每个 HAL 可选模块调用前必须 `hal_has()` 判空 | 评审 |
| R6 | 新平台适配只允许新增 `platform/<soc>/` 与 `profiles/*.json`；若需改 `core/`/`modules/` 视为 HAL 缺陷，先补接口 | PR 模板勾选 |
| R7 | 帧数据禁止拷贝；通过 `frame_bus_pull/release` 传引用 | 评审 |
| R8 | 日志禁止输出密码/验证码/token；使用 `log_mask()` | CI grep 关键字 |

| 日志 | `log.h` | 分级、模块级别、环形缓冲、脱敏 | 调用者线程 | — |

## 4. L3 功能模块

| 模块 | 依赖模块 | 订阅事件 | 发布事件 | 帧总线 | 配置键前缀 | 估算 RSS |
|---|---|---|---|---|---|---|
| `idp` | — | 全部（转协议上报） | BIND, STREAM | 直播/回放推流各 1 消费者 | `protocols.idp.*`, 全部 `cfg.*` 透传 | 3.5MB |

| `onvif` | rtsp | CONFIG, IVS（Events） | — | 无（引用 rtsp URL） | `protocols.onvif.*`, `image.*`, `video.*` | 1.5MB |
| `gb28181` | recorder（回放） | IVS, GPIO（Alarm） | STREAM | 实时 1、回放每会话 1 | `gb28181.*` | 2.5MB |
| `recorder` | — | IVS（事件录像）, STORAGE, CONFIG | RECORD | 每录像通道 1 消费者 | `record.*`, `storage.*` | 2MB |
| `ota` | idp（下发） | — | OTA | 无 | `ota.*` | 0.5MB（下载缓冲另计） |
| `console` | — | CONFIG | — | 抓图经 snapshot | `localUser.*` 等 | 0.5MB（复用 HTTP 服务） |
| `ivs` | — | — | IVS | 无（HAL 内部取 VI） | `alarm.*` | 0.5MB |
| `snapshot` | — | IVS（联动抓图） | — | 无（hal_video.snapshot） | — | 0.3MB |

### 4.1 关键交互

```
IVS 事件 ──event_bus──▶ recorder（事件录像）/ idp（event.motion）/ gb28181（Alarm）/ onvif（PullPoint）/ snapshot
GPIO 按键 ──event_bus──▶ idp（bind_state）/ core（复位）
STORAGE 插拔 ──event_bus──▶ recorder / idp（status）
CONFIG 变更 ──event_bus──▶ 各模块热应用；video.* 变更 → frame_bus 调用 hal_video.set_encoder
idp media.start ──▶ frame_bus_subscribe(ch) → RTMP push；media.stop → unsubscribe
gb28181 INVITE ──▶ frame_bus_subscribe(ch) → PS/RTP；BYE → unsubscribe
rtsp SETUP/PLAY ──▶ frame_bus_subscribe(ch)；TEARDOWN → unsubscribe
recorder 启用 ──▶ frame_bus_subscribe(main)（常驻消费者，占用 1 个名额）
```

## 5. 线程与资源模型

| 线程 | 归属 | 说明 |
|---|---|---|
| main | core | 启动、看门狗、健康巡检 |
| fb_ch0 / fb_ch1 | frame_bus | 每通道生产者 |
| evt | event_bus | 事件投递 |
| net | netmgr | 网络状态机 |
| idp | idp | MQTT 收发 + 命令处理；推流在 rtmp_push 内部线程 |
| rtsp | rtsp | 监听 + 每会话 1 线程（或单线程 epoll） |
| onvif/http | http_server | 单线程 epoll |
| sip | gb28181 | SIP 收发；媒体发送每会话 1 线程 |
| rec | recorder | 写盘 |
| ivs | ivs | HAL poll_event |

- 线程总数目标：V200 ≤ 14；每线程栈 ≤ 128KB（`pthread_attr_setstacksize`）。
- 内存预算由 `module_desc_t.footprint.rss_kb_estimate` 声明，启动器与 `profile.limits.mem_budget_mb` 比对，超出时按接入方案 §4.1.4 顺序降级并记日志。

## 6. 错误处理与状态

- HAL 错误码（`hal_err_t`）贯穿 L2/L3；协议层映射到各自错误码（IDP `E7xxx/E8xxx`、RTSP 4xx/5xx、SIP 4xx、ONVIF SOAP Fault）。
- 模块 `health()` 每 10s 由启动器调用；连续 3 次失败 → 重启该模块（stop/start）；模块重启 3 次仍失败 → 不喂狗触发整机重启并记录 `HAL_BOOT_WATCHDOG`。

## 7. 构建与测试约定

- CMake：`-DIPC_PLATFORM=mock|gk7205v200|…`、`-DIPC_PROFILE=SP-R1-02`；模块可选 `-DIPC_MOD_<NAME>=ON/OFF`。
- 目标板交叉编译由 Buildroot 外部树调用同一 CMake 工程。
- 测试：
  - `tests/hal_conformance`：任何平台必须通过的 HAL 黑盒测试（本次交付）。
  - `tests/core_*`：帧总线/配置/事件总线单测（x86 + mock）。
  - `tests/protocol_*`：RTSP/ONVIF/GB/IDP 一致性（对接 ZLM、ONVIF DTT、wvp、IDP 模拟平台）。
