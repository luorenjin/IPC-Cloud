# GK7205V200 模组烧录指南（只烧 rootfs）

把本仓库构建的控制台固件 `rootfs-console.64k.jffs2` 烧进模组的 rootfs 分区。**U-Boot、bootargs、内核都保留原厂版本不动**，烧坏了也能在 U-Boot 里重烧，模组不会变砖。

依据：原厂 `IPC Linux SDK开发环境配置指南.pdf` §2.5；烧录工具 `ToolPlatform-1.0.0-win32-x86_64`（界面文字取自工具中文语言包，实际布局可能略有差异）。

## 0. 板子 Flash 布局（2026-09-27 串口实测）

| 分区 | 起始 | 长度 | 本次是否烧写 |
|---|---|---|---|
| boot（U-Boot） | 0x000000 | 512K | 否 |
| bootargs | 0x080000 | 512K | 否 |
| kernel | 0x100000 | 5M | 否 |
| **rootfs** | **0x600000** | **10M（0xA00000）** | **是** |

> 只能用 `rootfs_partitions.xml`。它与板子一致；SDK 原版分区表（kernel 4M、rootfs@5M）不适用，已在 `docker/flash/` 替换。

## 1. 准备

### 1.1 文件

先执行 `cd firmware/docker && make -f Makefile fw-all`，确认 `firmware/docker/out/gk7205v200/spi_image/` 下有：

- `rootfs-console.64k.jffs2`：要烧的镜像（约 2.6MB，必须小于 10MB）
- `rootfs_partitions.xml`：完整四个分区，只勾选 rootfs

这两个文件**必须在同一目录**：分区表按相对路径找镜像。

### 1.2 硬件接线

1. **串口**：USB-TTL 模块接模组 UART0，TX↔RX 交叉，**GND 必须接**；**VCC 不接**，电平 3.3V。
   - 驱动：`国科微\最新国科微GK7205V200原厂SDK含DOME\usb_tools-usb串口烧录驱动.rar`；装完后在设备管理器里记下 COM 号。
2. **网线**：模组网口接到和电脑**同一个交换机/路由器**（电脑用有线网卡，不要用 WiFi）。
3. **电源**：DC 12V（5–12V 宽压）。先别上电。

### 1.3 电脑网络

- 电脑有线网卡 IP 要和模组在同一网段。按实测环境是 `172.16.1.x`（网关 `172.16.1.1`）。
- 给模组准备一个**没人用的**烧录用 IP，例如 `172.16.1.200`；先 `ping 172.16.1.200`，确认没有回应。
- Windows 防火墙：第一次运行工具时，放行 `javaw.exe` 的专用网络访问。工具内置的 TFTP 服务器用 UDP 69 端口，被拦截就会烧录超时。
- 关掉其他 TFTP 软件（如 Tftpd64），避免占用 69 端口。

### 1.4 串口终端

用 MobaXterm / SecureCRT / PuTTY 打开对应 COM 口：**115200 8N1，无流控**。上电看到 `System startup` 和 U-Boot 日志，说明串口正常。

**烧录工具要独占串口**：打开工具前，先在终端里**断开**串口连接。

## 2. 先备份原厂 Flash（强烈建议）

备份整片 16MB，以后可以完整恢复到出厂状态。

1. 启动 `ToolPlatform\ToolPlatform.exe`，芯片选 **GK7205V200**，打开 **BurnTool**。
2. 顶部配置：
   - **传输方式**：`网口（单板已有boot）`
   - **串口**：选 1.2 记下的 COM 号
   - **服务器 IP（PC 的 IP）**：选有线网卡的地址。列表里可能有 Docker/WSL 的 `vEthernet` 虚拟网卡，不要选它们
   - **板端配置**：IP `172.16.1.200`、子网掩码 `255.255.255.0`、网关 `172.16.1.1`、物理地址（MAC）填 `02:00:00:00:00:01`（只在烧录时临时用）
3. 切到 **按地址烧写** 页签：
   - Flash 类型：`spi`
   - 地址：`0x0`，长度：`0x1000000`（16MB）
   - 点 **上载**，文件保存为 `gk7205v200_factory_full_16M.bin`
4. 按提示**给模组上电（或断电重上电）**。工具会通过串口打断 U-Boot，再用网口 TFTP 回传数据。
5. 提示 **上载成功** 后，确认文件正好是 16,777,216 字节，把它妥善保存到仓库外面。

> 只想备份原厂 rootfs 的话：地址 `0x600000`，长度 `0xA00000`。

## 3. 烧录 rootfs（方式一：ToolPlatform，推荐）

1. 串口终端保持断开，工具顶部配置同第 2 步（传输方式 `网口（单板已有boot）`、串口、PC IP、板端 IP/掩码/网关/MAC）。
2. 切到 **按分区烧写**（或 `按分区烧写（spi/nand/emmc）`）页签。
3. **导入分区表**：选 `firmware\docker\out\gk7205v200\spi_image\rootfs_partitions.xml`。列表里应有四行，**只有 rootfs 被勾选**：

   | 勾选 | 名称 | Flash 类型 | 文件系统 | 起始 | 长度 | 文件 |
   |---|---|---|---|---|---|---|
   | ☐ | fastboot | spi | none | 0 | 512K | uboot_gk7205v200.bin |
   | ☐ | bootargs | spi | none | 512K | 512K | bootargs.bin |
   | ☐ | kernel | spi | none | 1M | 5M | uImage_gk7205v200 |
   | ✔ | rootfs | spi | none | 6M | 10M | rootfs-console.64k.jffs2 |

   核对 rootfs 起始是 **6M**、长度是 **10M**，且**只有它被勾选**。前三行只用来满足工具的格式要求（第一行必须是 fastboot），不勾选就不会被烧写。
4. ⚠️ **取消勾选「自动更新Bootargs分区中的mtdparts分区参数」**。
   勾着它，工具会改写原厂 bootargs 分区，没有必要，也有风险。
5. 点 **烧写**，按提示给模组**上电 / 断电重上电**。
6. 等待提示 **烧写成功**。10MB 分区走网口通常一分钟以内。
7. 模组断电重上电，让它从新 rootfs 启动。

## 4. 烧录 rootfs（方式二：U-Boot 命令行 + TFTP，工具出问题时用）

1. 电脑开一个 TFTP 服务器（如 Tftpd64），根目录指向 `firmware\docker\out\gk7205v200\spi_image\`。
2. 打开串口终端，上电后在 `Hit any key to stop autoboot` 出现时按任意键，进入 U-Boot 命令行。
3. 配置网络。只 `setenv`，**不要 `saveenv`**，重启后原厂环境变量不受影响：
   ```
   printenv ethaddr
   setenv ethaddr 02:00:00:00:00:01
   setenv ipaddr 172.16.1.200
   setenv netmask 255.255.255.0
   setenv serverip <电脑有线网卡IP>
   ping <电脑有线网卡IP>
   ```
   看到 `host ... is alive` 再继续。`ethaddr` 已经是合法地址的话可以不改。
4. 烧写。命令与 SDK 指南一致：先把内存填成 0xFF，再按整个分区擦除和写入：
   ```
   mw.b 0x41000000 0xFF 0xA00000
   tftp 0x41000000 rootfs-console.64k.jffs2
   sf probe 0
   sf erase 0x600000 0xA00000
   sf write 0x41000000 0x600000 0xA00000
   ```
   - `tftp` 结束时显示的 `Bytes transferred` 应等于镜像大小。
   - **`sf erase` 的地址必须是 `0x600000`**；写成 `0x0` 或 `0x100000` 会擦掉 U-Boot 或内核。
5. `reset` 重启。

## 5. 烧完后验证

打开串口终端，重新上电，依次应该看到：

1. 内核照常启动，`VFS: Mounted root (jffs2 filesystem) on device 31:3.`
   - 第一次启动可能出现几行 `jffs2: ... Empty flash at ...`，属于新镜像首次挂载的正常提示。
2. `[RCS]: /etc/init.d/S81dhcp`
   - 首次启动：`[S81dhcp] first boot, generated MAC 02:xx:xx:xx:xx:xx`
   - `[S81dhcp] eth0 MAC 02:xx:xx:xx:xx:xx`
   - `[udhcpc] eth0 got address 172.16.1.x`
3. `[RCS]: /etc/init.d/S90ipcapp`、`[S90ipcapp] starting console on port 8080`
4. 串口回车出现 shell，执行 `ps | grep ipc_app` 能看到进程。

然后在电脑浏览器打开 `http://<udhcpc 拿到的地址>:8080/`，应进入控制台的**首次激活**页面。

之后重启，`eth0 MAC` 应保持不变，IP 通常也不变，可以在路由器里给这个 MAC 做地址保留。

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 导入分区表报「不合法的分区表文件」 | 工具要求**第一行必须是 `fastboot`**；用本仓库 `rootfs_partitions.xml`（四行，只勾 rootfs），不要自己删成只剩 rootfs 一行 |
| 「发送起始帧失败」+ `Failed to Download Boot!` | 工具要在芯片刚上电时通过串口和 BootROM 握手。检查：① 点烧写后 15 秒内**彻底断电再上电**（拔 DC 插头，不是按复位）；② 串口终端已断开、COM 号正确；③ USB-TTL 的 TX 真正接到板子 RX（在串口终端上电时按键能停在 U-Boot 即说明接通）；④ 断电时板子没有被 USB-TTL 的 TX/VCC 倒灌供电（指示灯没全灭就是被倒灌）。仍失败就改用第 4 节 U-Boot 命令行烧写 |
| 工具报「请选择串口」或串口打不开 | 串口终端没断开；或 COM 号选错 / 驱动没装 |
| 工具报「板端IP与PC的IP不在同一个网段」 | 服务器 IP 选成了虚拟网卡，或板端 IP 网段填错 |
| 工具报「TFTP服务器启动失败，端口69可能被占用」 | 关掉 Tftpd64 等 TFTP 软件；或防火墙拦截了 `javaw.exe` |
| 一直等不到板子响应 | 没有按提示给板子重新上电；网线没接或不在同一交换机 |
| 启动卡在 `VFS: Cannot open root device` / 反复重启 | 起始地址或 bootargs 被改错（多半是第 3.4 步没取消勾选）。用第 7 节恢复 |
| 有 IP 但浏览器打不开 8080 | 串口里看 `cat /var/log/ipc_app.log` 并反馈 |
| 没有 `udhcpc ... got address` | 路由器没开 DHCP；串口执行 `ifconfig eth0` 看是否 up 以及 MAC |

## 7. 恢复出厂

用第 2 步的备份，选**按地址烧写**：

- 整片：Flash 类型 `spi`，地址 `0x0`，长度 `0x1000000`，文件 `gk7205v200_factory_full_16M.bin`，点 **烧写**。
- 只恢复 rootfs：地址 `0x600000`，长度 `0xA00000`，文件为原厂 rootfs 备份。

也可以在 U-Boot 命令行里用第 4 节的命令，把文件名换成备份文件；整片恢复时地址用 `0x0`、长度用 `0x1000000`。

## 8. 注意

- 以后整分区重烧 rootfs，会清掉 `/etc/ipc/mac`（固定 MAC）和 `/etc/ipc/config.json`（控制台配置、激活状态）。下次开机会生成新 MAC，并重新进入首次激活。
- 不要用整片分区表（`spi_partitions.xml`）烧 U-Boot / 内核，除非量产 MAC 方案已经确定，且 SDK 编出的 U-Boot / 内核已在这块板子上验证过。
