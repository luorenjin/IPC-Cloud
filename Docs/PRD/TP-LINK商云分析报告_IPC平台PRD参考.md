## 1. 执行摘要

### 1.1 核心结论

TP-LINK 商云是一个**以 TP-LINK 自有硬件为闭环、面向多业态（网络/安防/充电/广播/价签）的 SaaS 运维平台**。其视频监控子系统（"监控管理"）在产品设计上有四个值得 IpcCloud 直接借鉴的特点：

1. **接入极简化**：设备通过"设备 ID / 二维码 / 局域网自动发现 / 预添加激活"四种低门槛方式上云，用户**无需公网 IP、无需输入设备用户名密码即可远程管理**（问题指南-通用），本质上是设备侧主动向云注册（云管理模式）。
2. **组织树 + 监控点粒度权限**：`TP-LINK ID → 企业 → 项目 → 4 级设备分组 → 设备/监控点`，角色权限可细化到具体监控点（角色与成员/添加角色）。
3. **模板化配置**：录像计划、布防时间、H5 直播页均采用"固定模板 + 用户自定义模板"的模式，批量应用到多个监控点，并声明"修改模板后使用该模板的监控点将同步更新"。
4. **成本可见与可控**：视频转发流量按监控点统计、可设小时/日/月上限、超限自动禁播；直播按 GB 计费；云存储/播放通道按套餐售卖。

### 1.2 与 IpcCloud 的关键差异

| 维度 | TP-LINK 商云 | IpcCloud 定位 |
|---|---|---|
| 设备生态 | 仅 TP-LINK 全系摄像机/NVR，第三方需经 TP-LINK NVR 中转 | **开放接入**：ONVIF / RTSP / GB28181 / RTMP 推流，多品牌 |
| 部署模式 | 公有云 SaaS，设备主动注册至 `tplinkcloud.com.cn` | **私有化 / 混合部署**，ZLMediaKit 自持流媒体 |
| 发现机制 | 依赖 TP-LINK 网络设备做"智能配置"发现 | ONVIF WS-Discovery + IP 段扫描 + GB28181 注册 |
| 播放协议 | HLS（直播分享），Web 预览为私有免插件方案 | WebRTC（低延时）/ HTTP-FLV / HLS 分层 |
| 远程配置 | 跳转设备 Web 或私有协议 | ONVIF Media/PTZ/Imaging 标准化配置 |

### 1.3 产出一览

- **功能需求清单**：P0 42 项 / P1 31 项 / P2 19 项（见第 7 章）
- **交互设计参考**：7 类关键页面布局、6 条核心流程、反馈与错误提示策略（第 8 章）
- **技术方案**：ZLMediaKit 协议适配矩阵、Go 后端 9 个领域模块、Nuxt 前端播放器分层、参考开源项目（第 9 章）

## 3. TP-LINK 商云总体模型

### 3.1 使用流程（手册原图）

```
登录商云平台/商云APP → 注册 TP-LINK ID → 创建项目 → 添加设备 → 分配管理权限 → 项目管理运维
```

首次登录自动进入**设置向导**：创建企业 → 创建项目（选择项目类型）→ 进入工作台。

### 3.2 信息架构（IA）

```
TP-LINK ID（个人账号，可关联多企业）
└── 企业（Enterprise）
    ├── 成员 / 角色 / 成员审核
    ├── 费用（余额、订单、卡券、服务通知）
    ├── 开发者（应用、密钥、开放设备）
    └── 项目（Project，可多个）
        ├── 首页：设备运行概览 / 告警概览 / 最近操作 / 消费统计
        ├── 通用：设备管理（设备列表 / 设备分组≤4级 / 添加 / 排序） / 拓扑结构 / 地图定位
        ├── 网络管理：（略）
        ├── 监控管理：
        │   ├── 视频监控：视频预览（预览/回放） / 流量控制 / 流量统计 / 播放增值服务 / 客户端下载
        │   ├── 报警设置：监控点报警 / 设备异常报警
        │   ├── 录像设置：录像计划模板 / 添加录像设置 / 管理录像设置
        │   ├── 实时直播：开通直播 / 直播管理 / H5 模板 / 直播统计
        │   ├── 云存储：开通 / 设置 / 套餐转移
        │   ├── AI 算法管理：导入算法 / 管理设备上的算法
        │   ├── 客流数据统计 / 车辆管理 / 4G 流量充值
        ├── 系统：日志 / 消息
        └── 高级应用 / 行业应用（略）
```

### 3.3 核心实体关系（推断）

```
Enterprise 1─* Project 1─* DeviceGroup(tree, depth≤4) 1─* Device
Device(IPC | NVR) 1─* Channel（"监控点"= IPC 本体或 NVR 通道）
Channel 1─0..1 RecordPlan（引用 RecordTemplate）
Channel 1─* AlarmRule（事件类型 × 布防时间模板）
Channel 1─0..1 LiveStream（HLS 主/子码流地址、H5 页、观看时段）
Channel 1─0..1 CloudStorage（套餐、上传开关）
Channel 1─0..1 TrafficLimit（小时/日/月上限、禁播开关）
Role *─* Channel（视频权限到监控点粒度）
```

> **设计启示**：商云用"监控点（Channel）"而非"设备"作为视频业务的一等公民，IPC 和 NVR 通道被统一抽象。IpcCloud 应沿用 `Device → Channel` 两层模型，GB28181 的 Device/Channel、ONVIF 的 Device/Profile 都能自然映射。

## 4. 详细分析

### 4.1 账户、组织与权限模型

| 要素 | 商云实现 | 来源 |
|---|---|---|
| 账号体系 | 统一 TP-LINK ID，Web / PC 客户端 / APP 三端通用 | 注册登录概述 |
| 企业 | 一个 ID 可关联多企业；企业下有主账号（首个可见"开发者"菜单） | 创建企业、开发者服务简介 |
| 项目 | 企业下多项目；创建时选"项目类型"（影响首页功能模块） | 创建项目 |
| 设备分组 | 项目内树形分组，最多 4 级；支持添加/子分组/重命名/删除/上移下移 | 设备分组 |
| 角色 | 自定义角色，权限按模块（通用/监控/网络/…）勾选；**监控管理权限需勾选具体监控点**；支持"复用其他角色的参数" | 添加角色 |
| 成员 | 子账号 + 角色；成员审核机制；超级管理员不可移除 | 成员管理、FAQ |
| 分享方式 | "将监控画面分享给他人" = 创建子账号（无匿名分享链接，仅直播功能有公开 URL） | FAQ |

**IpcCloud 借鉴点**：
- 采用 `租户(Tenant) → 项目(Project) → 分组树(Group) → 设备/通道` 四层。
- RBAC 授权对象必须支持**通道级**（Channel-level）资源范围，而非仅菜单级。
- 保留"角色复制"快捷操作。

### 4.2 设备接入机制

#### 4.2.1 五种添加方式全景

| # | 方式 | 适用设备 | 输入要素 | 认证方式 | 批量 | 关键流程 | 来源 |
|---|---|---|---|---|---|---|---|
| 1 | **设备 ID 添加** | 全部 TP-LINK 设备（含 IPC/NVR） | 17 位设备 ID（机身标贴）、设备名称、所属分组 | 设备已联网上云 + ID 匹配（无需密码） | 支持，Excel 模板导入（ID/用户名/密码） | 输入 ID → `查找设备` → 绑定 | 添加设备 |
| 2 | **MAC 地址添加** | 网络设备（非 IPC） | MAC、本地 Web 用户名/密码 | 用户名密码校验 | 支持 | — | 添加设备 |
| 3 | **智能配置添加**（局域网自动发现） | 依赖网内存在"支持智能配置"的 TP-LINK 网络设备 | 统一设置出厂设备的用户名/密码 | 出厂设备自动绑定；已设密码设备需手动验证 | 天然批量 | 发现全网拓扑 → 有线配置 → 无线配置 → 场景化配置 → 下发 | 添加设备 |
| 4 | **来自物联 APP** | 已绑定在 TP-LINK 物联 APP 的 IPC/NVR 通道 | 24h 有效二维码/链接 | 物联账号验证 + 重设设备密码 | 支持多选 | 转移（解绑原 APP）/ 分享（保留原绑定，授予预览/回放/对讲/云台权限） | 添加设备 |
| 5 | **设备预添加** | 有设备 ID 或 SN 的未上线设备 | Excel：ID/SN、名称、安装位置、用户名、密码 | 7 日内用商云 APP 扫项目鉴权二维码激活 | 支持 | 导入 → "预添加设备"标签 → 现场激活 → 自动绑定并下发配置 | 添加设备 |
| 6 | 其他 | — | APP 扫机身二维码；PC 客户端局域网自动发现批量添加监控设备 | — | 支持 | — | 添加设备、FAQ |

#### 4.2.2 接入前置条件与失败处理

| 项 | 商云做法 |
|---|---|
| 前置提示 | 弹窗顶部固定提示："请确认需要添加的设备都已接入互联网" |
| "未联网"排障 | FAQ 给出两条：① 设备 DNS 无法解析云域名 → 改 DNS 114.114.114.114；② 线路封锁云服务器 → 换线路 |
| 预添加失败 | 保留在"预添加设备"标签内，可查看具体失败原因 |
| 已绑定冲突 | 转移流程要求先解绑；设备复位后联网即解绑原项目 |
| 解绑方式 | ① 云端删除设备；② 设备本地 Web 关闭云管理；③ 设备复位 |
| 空状态 | 无设备时显示插画 + "立即添加设备"主按钮 + "设备标定表"导入入口 |

#### 4.2.3 对 IpcCloud 的映射

| 商云方式 | IpcCloud 对应方案 | 类型 |
|---|---|---|
| 设备 ID 添加 | **GB28181 注册接入**：平台生成 SIP 服务器 ID/域/密码，设备侧填写后主动注册；平台列表出现"待确认设备"，管理员确认入库 | 改造 |
| 智能配置添加 | **ONVIF WS-Discovery 自动发现** + **IP 段扫描（RTSP 554 / ONVIF 80/8080 探测）**，在"发现结果"页批量填凭据并添加 | 改造 |
| MAC 地址添加 | **手动添加**：IP/端口/用户名/密码 → 选择协议（ONVIF 自动探测 Profile / 手填 RTSP URL） | 改造 |
| 批量导入 ID | **Excel/CSV 批量导入**（IP、协议、凭据、名称、分组） | 复用 |
| 设备预添加 | **GB28181 白名单预注册**（预填国标 ID、密码；设备一注册即自动落入指定分组） | 复用 |
| 物联 APP 转移 | 不适用（无外部 C 端 APP）；可替换为 **RTMP/SRT 推流接入**（平台生成推流地址） | 我方增强 |

### 4.4 流媒体处理逻辑

#### 4.4.1 架构推断

从以下事实可推断商云为**云端中继（Relay）架构**：

- "商云统计的视频监控流量为商云服务器转发所消耗的流量，并非监控点消耗的流量"
- "平台对每个摄像机免费提供一定路数的视频转发，超过时可开通付费服务"（视频播放增值服务：额外播放通道、不限时长）
- 直播地址形如 `https://live-hls-tums.tplinkcloud.com.cn:8100/store/{hlsId}/0/{uuid}/playlist.m3u8`（`/0/` 主码流、`/1/` 子码流）
- "开启流量控制后无法预览和回放，直播功能不受影响" → 预览/回放与直播是两套转发通道

```
IPC/NVR ──(私有协议主动连接)──▶ 商云接入服务器 ──▶ 转发集群 ──▶ Web/APP/客户端（免插件）
                                              └──▶ HLS 切片服务 ──▶ H5 直播页 / 第三方（小程序 API 取 m3u8）
                                              └──▶ 云存储（仅移动侦测录像上传）
```

[1] 管理员登录（本地账号 / SSO）→ 首次向导：创建租户/项目、配置流媒体节点（ZLMediaKit 地址/secret 自检）

## 6. 对比分析：商云 vs IpcCloud

### 6.1 逐模块对比

| 模块 | 商云 | IpcCloud 方案 | 差异性质 |
|---|---|---|---|
| 设备发现 | 依赖 TP-LINK 网络设备"智能配置"；PC 客户端局域网发现 | ONVIF WS-Discovery、IP 扫描、GB28181 注册、mDNS（可选） | 我方更开放 |
| 认证 | 设备 ID 即可绑定（云端预置信任）；网络设备需用户名密码 | ONVIF/RTSP Digest 用户名密码；GB28181 SIP 密码；平台保存加密凭据 | 我方需处理凭据管理 |
| 协议 | 私有协议 | ONVIF Profile S/T、RTSP、GB28181-2016/2022、RTMP/SRT 推流 | 我方更开放 |
| NAT 穿透 | 设备主动出连，天然穿透 | 局域网直连；跨网需 GB28181 注册或 RTMP 推流 或 边缘 ZLM 节点级联 | 商云更简单 |
| 预览协议 | 私有免插件 + HLS 直播 | WebRTC（首选，<500ms）/ HTTP-FLV（兼容）/ HLS（分享） | 我方低延时 |
| 多画面 | Web 单画面，客户端多画面 | Web 端 1/4/9/16 分屏 | 我方增强 |
| 录像 | 设备端录像 + 云存储活动录像 | ZLM 服务端 MP4 录像（全天/事件） + 设备端录像回放（GB28181/ONVIF Replay） + 对象存储归档 | 我方双轨 |
| 回放 | 时间轴、9 档倍速、截图、电子放大、快进 30s | 同 + 下载片段 + 多通道同步回放（P2） | 基本对齐 |
| PTZ | 有（权限维度可见），Web 端未见控件 | ONVIF PTZ ContinuousMove/AbsoluteMove/Preset；GB28181 PTZ 指令 | 我方补全 |
| 告警 | 设备端智能事件上报 + 布防模板 | ONVIF Events (PullPoint) / GB28181 Alarm / 流断告警 + 布防模板 | 对齐 |
| 固件升级 | 在线自动检测 + 本地上传 + 定时 | 本地上传（ONVIF `UpgradeSystemFirmware`，厂商兼容性有限）+ 定时；不承诺在线源 | 商云更强（闭环优势） |
| 流量控制 | 每点小时/日/月上限 | ZLM `on_flow_report` 统计 + 后端限流策略；私有部署下优先级低 | 降级 P2 |
| 直播分享 | H5 页 + m3u8 + 时段控制 + 计费 | 分享链接（HLS/FLV）+ 有效期/时段/密码 + 访问统计；无计费 | 简化 |
| 权限 | 角色到监控点 | 同 | 对齐 |
| 开放 API | 开发者平台 | OpenAPI + AppKey | 对齐 |
| 计费/套餐 | 余额、订单、卡券 | 不适用（私有部署） | 移除 |

### 6.2 商云值得直接复用的设计决策

1. **通道（监控点）为核心**，所有视频业务（录像/告警/直播/存储/流量）都挂在通道上。
2. **模板机制**（录像/布防）+ "同步更新"提示。
3. **三步向导** 统一格式：选对象 → 选策略 → 选时间/参数。
4. **设备列表工具栏 + 列配置 + 筛选 + 批量搜索 + 导出** 的重型表格模式。
5. **预添加 / 待激活** 的"先规划后上线"流程。
6. **操作记录三件套**：重启记录 / 升级记录 / 诊断记录（含成功/失败明细、按天筛选）。
7. **消息中心分类 + 详情字段规范**。

### 6.3 商云的不足（IpcCloud 机会点）

| 不足 | 机会 |
|---|---|
| Web 端仅单画面 | 提供分屏与轮巡 |
| 无设备健康指标（码率/帧率/丢包/CPU/存储） | 流健康仪表盘 |
| 无统一错误码 | 定义错误码与排障建议 |
| 无固件回退 | 保留上一版本固件包，支持回滚（依赖设备能力） |
| 无录像下载（Web） | 支持片段下载与导出任务 |
| 第三方摄像机需经 NVR | 原生多协议接入 |
| 分享只能建子账号 | 临时分享链接（有效期/密码/水印） |

### 8.4 错误提示策略

商云的 FAQ 实质上是错误提示的外置版本（如"添加提示未联网 → 检查 DNS/线路"）。IpcCloud 应将其**内置为错误码 + 建议**：

| 错误码 | 场景 | 用户文案 | 建议动作 |
|---|---|---|---|
| E1001 | 设备不可达 | 无法连接到 192.168.1.10:80 | 检查网线/IP/防火墙；[Ping 测试] |
| E2001 | 认证失败 | 用户名或密码错误 | 修改凭据；确认设备未锁定 |
| E2002 | ONVIF 未启用 | 设备未开启 ONVIF 或版本不兼容 | 在设备 Web 开启 ONVIF；改用 RTSP 直连 |
| E3001 | RTSP DESCRIBE 失败 (404) | 码流地址不存在 | 核对 RTSP 路径；使用 ONVIF 自动获取 |
| E3002 | 编码不支持 | 设备输出 MJPEG/SVAC，浏览器无法解码 | 在设备端改为 H.264 |
| E4001 | 流媒体节点离线 | 流媒体服务不可用 | 检查 ZLMediaKit 进程/网络 |
| E4002 | 拉流超时 | 10 秒内未收到数据 | 检查设备带宽；切换 TCP 传输 |
| E5001 | 磁盘空间不足 | 录像目录剩余 <5% | 清理或扩容；调整保留天数 |
| E6001 | GB28181 注册密码错误 | 设备注册被拒绝 | 核对平台密码 |

### 8.5 与商云的异同点总结

| 维度 | 相同 | 不同 |
|---|---|---|
| 信息架构 | 项目 → 分组树 → 设备/通道；模块化侧栏 | 去除计费/费用/行业模块；增加流媒体节点 |
| 添加流程 | Tab 分方式、批量导入模板、前置提示 | 发现基于 ONVIF/扫描；国标注册替代设备 ID |
| 列表 | 工具栏 + 列配置 + 筛选 + 导出 | 增加协议/流状态/诊断 |
| 播放 | 预览/回放同页 Tab、工具栏图标语义 | Web 多画面 + PTZ 面板 |
| 模板 | 周 × 24h 编辑器、级联提示 | 显示受影响数 |
| 反馈 | 成功/失败列表 | 任务中心、错误码 |

## 9. 技术实现方向

### 9.1 总体架构

```
┌──────────────────────────── Nuxt.js 前端 (SSR/SPA) ─────────────────────────────┐
│ 页面：仪表盘 / 设备 / 预览 / 回放 / 告警 / 分享 / 系统                            │
│ 播放器层：WebRTC(ZLM WHEP) → HTTP-FLV(mpegts.js/jessibuca) → HLS(hls.js) 自动降级 │
│ 实时：WebSocket（状态/告警/任务进度）                                              │
└───────────────┬───────────────────────────────────────────────────────────────┘
                │ REST(JSON) / WebSocket
┌───────────────▼──────────────── Go 后端 (单体模块化，可拆微服务) ─────────────────┐
│ api-gateway │ auth/rbac │ device │ channel │ discovery(onvif/scan) │ gb28181(sip) │
│ stream(zlm-client) │ record │ alarm │ share │ task │ notify │ audit │ media-node   │
│ 存储：PostgreSQL（元数据） Redis（状态/会话/锁） 本地磁盘/MinIO（录像/快照）       │
└──────┬─────────────────────┬────────────────────────────┬───────────────────────┘
       │ REST API + secret   │ Web Hook (HTTP POST)       │ SIP/UDP-TCP 5060 & RTP
┌──────▼─────────────────────▼────────────┐   ┌───────────▼─────────────────────┐
│ ZLMediaKit 节点 ×N                       │   │ IPC / NVR / 国标平台            │
│ RTSP proxy / RTMP publish / GB28181 RTP │◀──│ ONVIF (SOAP) / RTSP / GB28181   │
│ → WebRTC / FLV / HLS / MP4 record       │   └─────────────────────────────────┘
└─────────────────────────────────────────┘
```

### 9.2 协议适配矩阵

| 接入协议 | 发现 | 认证 | 取流方式（ZLM） | 控制 | 事件 | 设备端回放 |
|---|---|---|---|---|---|---|
| **ONVIF** | WS-Discovery（UDP 3702 多播） | WS-UsernameToken Digest | `GetStreamUri` → `addStreamProxy(rtsp://…)` | PTZ / Imaging / DeviceMgmt SOAP | Events PullPoint 订阅 | Profile G `GetRecordings` + Replay（设备支持度低，P1 验证） |
| **RTSP 直连** | IP 扫描 554 | RTSP Digest（URL 内嵌） | `addStreamProxy(url, rtp_type=0 TCP)` | 无 | 仅流断 | 无 |
| **GB28181** | 设备主动 REGISTER | SIP Digest（平台密码） | `INVITE` → ZLM `openRtpServer` 收 PS 流 → 自动转协议 | PTZ / TeleBoot / 录像控制 (MANSCDP) | Alarm 通知、Keepalive | `RecordInfo` + 回放 INVITE（Playback），支持倍速/拖动 |
| **RTMP/SRT 推流** | 无 | `on_publish` 校验 stream key | 设备推到 ZLM | 无 | 仅流断 | 无 |

### 9.3 ZLMediaKit 关键能力使用

| 目的 | ZLM 接口 / Hook | 后端处理 |
|---|---|---|
| 按需拉流 | `on_stream_not_found` → 后端 `addStreamProxy`；`on_stream_none_reader` → `delStreamProxy`/`close_streams` | 实现"有人看才拉"，闲置超时可配（建议 30~60s） |
| 流状态 | `on_stream_changed`（regist=true/false） | 更新 Redis 通道流状态，推 WebSocket |
| 播放鉴权 | `on_play`（携带 token 参数） | 校验 JWT + 通道权限（对应商云"监控点权限"） |
| 推流鉴权 | `on_publish` | 校验 stream key（推流接入） |
| 流量统计 | `on_flow_report` | 每通道/每用户流量落库（对应商云流量统计） |
| 录像 | `startRecord(type=1 mp4, max_second)` / `on_record_mp4` | 按录像计划开关；回调写录像索引（通道、起止、路径、大小） |
| 回放 | 服务端 MP4：ZLM 点播 `/record/…mp4` 或后端按时间段合成；设备端：GB28181 Playback | 时间轴数据由索引表生成 |
| 快照 | `getSnap(url, timeout_sec, expire_sec)` | 添加设备后封面、告警联动快照 |
| 国标收流 | `openRtpServer(port, tcp_mode, stream_id)` / `closeRtpServer` | SIP INVITE 的 SDP 用该端口 |
| 转推 | `addStreamPusherProxy` | 分享到第三方 RTMP 平台 |
| 节点健康 | `on_server_started` / `on_server_keepalive` / `getThreadsLoad` | 节点在线判定与负载调度 |
| 踢流 | `kick_sessions` | 权限收回、并发上限 |
| 低延时播放 | WebRTC（`/index/api/webrtc?app=&stream=&type=play`，WHEP） | 前端首选 |

**配置建议**（`config.ini`）：
- `[general] enable_audio=1, mediaServerId=唯一`；`[hook] enable=1, timeoutSec=10, retry=2`
- `[protocol]`：`enable_hls=1, enable_mp4=0（由 startRecord 控制）, enable_rtsp=1, enable_rtmp=1, enable_fmp4=1`
- `[record] fileSecond=600`（10 分钟切片）
- `[rtp_proxy] port_range=30000-30500`（国标）
- `[api] secret=随机 32 位`，仅内网可达

### 9.4 Go 后端模块设计

| 模块 | 职责 | 关键依赖（建议） |
|---|---|---|
| `auth` | 登录、JWT、RBAC（资源到通道级） | `golang-jwt`, casbin（可选） |
| `device` / `channel` | 元数据、状态机（Added→Probing→Online/Offline/Error）、凭据加密 | `gorm`/`sqlc`, `crypto/aes` |
| `discovery` | WS-Discovery、IP 扫描、结果缓存 | `github.com/gowvp/onvif`（或 `use-go/onvif`） |
| `onvif` | DeviceMgmt / Media / PTZ / Imaging / Events 封装 | 同上 |
| `gb28181` | SIP UAS/UAC（REGISTER/INVITE/MESSAGE）、目录、心跳、PTZ、录像查询/回放 | 参考 `gowvp/owl`（内嵌 `panjjo/gosip`） |
| `stream` | ZLM REST 客户端 + Hook Handler + 节点调度 | `net/http`, 可参考 `zlm-spring-boot-starter` 的接口覆盖面 |
| `record` | 录像计划调度（cron）、索引、保留清理、下载合成 | `robfig/cron`, ffmpeg（合成） |
| `alarm` | 事件归一化、布防匹配、去重（同事件 N 秒内合并）、通知 | `asynq`/自建队列 |
| `task` | 长任务（发现/导入/升级/下载）状态与进度 | Redis |
| `notify` | WebSocket Hub、邮件、Webhook | `gorilla/websocket` |
| `audit` | 操作日志中间件 | — |
| `medianode` | 节点注册、健康、负载均衡（最少流数/加权） | — |

**状态判定策略**（对应商云"在线/离线"）：
- ONVIF/RTSP 设备：每 30s `GetSystemDateAndTime` 或 TCP 探测；连续 3 次失败 → 离线。
- GB28181：Keepalive 超时 ×3 → 离线。
- 推流设备：`on_stream_changed regist=false` 后 30s 无重新注册 → 离线。
- 流级状态独立于设备状态（设备在线但拉流失败 → `Error` 并带错误码）。

## 10. 风险、约束与待决策项

### 10.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| ONVIF 实现差异大（Events/Profile G/固件升级支持度低） | 事件与设备端回放在部分品牌不可用 | 以 GB28181 为跨品牌事件/回放主路径；ONVIF 能力探测后按能力灰显功能 |
| 浏览器不支持 H.265 WebRTC（部分） | 主码流 H.265 无法 WebRTC 播放 | 降级 FLV（软解，jessibuca）或引导设备切 H.264；子码流强制 H.264 |
| 跨网接入无 NAT 穿透 | 与商云"零配置远程"差距 | GB28181 注册 / 推流 / 边缘 ZLM 级联（`addStreamProxy` 拉边缘） |
| 录像 IO 与磁盘 | 全天录像 200 路 × 4Mbps ≈ 8.6TB/天 | 默认事件录像 + 子码流全录；对象存储归档 |
| 凭据安全 | 设备密码泄露 | 加密、脱敏、最小权限、审计 |

### 10.2 待决策项

1. **是否在 MVP 纳入 GB28181**（P0 建议纳入，跨网与 NVR 场景刚需）。
2. **服务端录像默认策略**：全天子码流 vs 仅事件 vs 不录（依赖设备端）。
3. **是否提供公开分享链接**（安全合规视角）。
4. **前端 UI 库**与**播放器**选型（jessibuca 商业授权 vs mpegts.js 开源）。
5. **多节点调度策略**与节点级联（边缘部署）是否在 P1。
