## 1. 背景与问题

### 1.1 现状问题（v1 控制台）

| 问题 | 表现 | 用户影响 |
|---|---|---|
| **功能面过窄** | 仅系统信息 / 网络 / 简单配置 / 归属 | 无法完成「装一台摄像机」的日常管理 |
| **无视频** | 无预览、无码流切换 | 无法验收画面与镜头 |
| **无事件与录像** | 无移动侦测、无录像/抓图计划 | 无法当安防机用 |
| **无图像调参** | 无亮度/宽动态/日夜/补光 | 夜间与逆光场景不可用 |
| **无下载取证** | 无按事件检索图片 | 出警/纠纷无法导出 |
| **信息架构弱** | 平铺 Tab | 对比 TP-LINK「预览/工具/设置」三区，心智成本高 |

### 1.2 对标结论（实机可见）

TP-LINK 本地 Web 已形成完整 **「看 → 查 → 管」** 闭环，我方固件控制台必须达到同级可用性，才能：

1. 产线/实施 **不开云** 就能完成安装验收；  
2. 现场排障不依赖 NVR/客户端；  
3. 为 IpcCloud 云管提供稳定设备侧能力底座。

> **定位**：设备本地管理 = 安装/调参/取证/排障；**IpcCloud** = 多设备运维与分权。两者不互相替代。

## 5. 功能需求

> 优先级：**P0** = 本地验收必备；**P1** = 首个正式固件；**P2** = 后续。

### 5.1 账号与会话（P0）

| 编号 | 需求 | 验收 |
|---|---|---|
| LC-AUTH-01 | 首次访问强制设管理密码（admin） | 未设密不可进主界面 |
| LC-AUTH-02 | 登录/登出；错误提示不区分「用户不存在」 | 连续 5 次锁定 15 分钟 |
| LC-AUTH-03 | 会话超时（默认 30min）与修改密码 | 超时回登录页 |
| LC-AUTH-04 | 用户管理：改密、（P1）只读账号 | 见实机「用户管理」 |

### 5.2 预览（P0）

| 编号 | 需求 | 验收 |
|---|---|---|
| LC-PV-01 | 实时预览（浏览器，WS-FLV/HTTP-FLV 或 MJPEG 降级） | 局域网首帧 ≤1.5s |
| LC-PV-02 | **主码流 / 子码流**切换 | 切换 ≤2s；状态回显 |
| LC-PV-03 | 显示比例 4:3 / 16:9 / 100%（对齐实机）；**四档都不得裁切画面**——OSD 是设备烧进码流的（LC-OSD-11），按比例裁剪会切掉左对齐的通道名与时间串（2026-10-01 真机实测修正，见遗留清单「九追加」） | 与实机交互一致；四档下 OSD 均完整可见 |
| LC-PV-04 | 单播/组播提示（本机未使能组播则灰显，对齐实机文案） | 不出现假开关 |
| LC-PV-05 | 截图 PNG、全屏、音量/静音（有音频时） | 截图原始分辨率 |
| LC-PV-06 | **预览自愈**（2026-10-01 真机黑屏事故后补）：编码取流连续 3 秒无帧 → HAL 内部重启该编码通道（Stop/Start + 请求 IDR）；连续 **8 秒**一帧都取不到 → 预览层重建整条视频通路（close + open + start + 请求 IDR）。目的：把“永久黑屏、只能整机重启”压成“最多 8 秒自愈”，并在 `/var/log/ipc_app.log` 留下带错误码的记录 | 8 秒内自愈；日志可定位 |

### 5.11 时间与时区的实现口径（2026-10-01 补充，LC-SYS-01 / LC-SYS-07）

- **设备无 RTC**：墙钟开机从 0 起算，靠 NTP 校时；`time.ntp.enable` 未配置时按**开启**处理
  （唯一读取入口 `console_ntp_read()`，显示与实际起 ntpd 同源）。
- **本机（板端）没有 zoneinfo 数据库**（实测 `ls /usr/share/zoneinfo` 为空），所以 `time.timezone`
  只能是 **POSIX 偏移写法**：`CST-8`(=UTC+8)、`UTC-5:30`(=UTC+5:30)、`UTC0`。区名
  （`Asia/Shanghai`）**存得进但不生效**（libc 退回 UTC），因此控制台接口按「能解出数值偏移」校验，
  直接拒掉区名而不是静默接受。
- **POSIX 符号与直觉相反**：`local = UTC − offset`，故东八区写作 `-8`；页面下拉的 `(UTC+08:00)`
  对应值 `CST-8`。
- **时区影响面**：进程 TZ 经 `os_set_timezone()`（core/os，唯一 `_WIN32` 分支）设置——启动时由
  `app/main.c` 设一次，运行期改时区由 `PUT /api/v1/system/time` 调 `console_apply_timezone()` 立即重设；
  OSD 时间叠加走 `localtime_r`、定时重启/日夜定时读 cfg、页面按「utc + 偏移」自算，三处随之同步。
- **为什么页面不用浏览器时区**：设备时区与浏览器时区可以不同（本来就是本功能的目的），
  用浏览器 getter 显示会让页面时钟与画面上 OSD 差若干小时；前端统一把「设备本地墙钟」当作 UTC
  时刻再用 `getUTC*` 格式化（见 `firmware/web/js/views/system.js` 的 `tzOffsetMin` 注释）。
- **实机差异**：对标实机的 `str.js` 全文无 时区/UTC/GMT 字样，即**实机没有时区设置项**，本行是
  本方新增能力，不构成“未对齐”。

## 10. 验收清单（摘要）

1. 未设密 → 强制激活；登录后顶栏为 **预览 | 工具 | 设置**。  
2. 预览可切主/子码流与 4:3/16:9/100%。  
3. 工具可按类型检索并下载图片。  
4. 设置九树可见；P0 页均可保存并刷新回读。  
5. 录像计划网格可涂改并保存。  
6. 无 WiFi/无算法时对应项隐藏或「不支持」，无假开关。  
7. **存储管理双分支**：`tfPresent=true` 显示容量表+格式化+可编辑配额；`tfPresent=false` 显示空态+禁用；录像/抓图计划在无卡时横幅禁用。固件对齐须覆盖两分支（LC-ST-04/05/06）。
8. **平台接入三分支**：IpcCloud / GB28181 / GA/T 1400 切换后表单字段互斥、注册状态文案正确；无 TUMS。
