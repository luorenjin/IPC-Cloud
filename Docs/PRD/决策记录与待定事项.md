---

## 1. 优先顺序

```
① 平台（云/服务端 + Web）  →  ② 设备接入（协议与流程）  →  ③ 固件通用层（L2/L3 + HAL 接口）  →  ④ 硬件与固件底层（待芯片/传感器/ISP/Flash 定后）
```

前三项现在推进；第四项**只做接口预留，不做实现决策**。

### 2.4 待决策：远程配置能力取舍（与竞品对齐项）

**背景**：对照竞品（TP-LINK 商云）的设备远程配置面板逐项核对后，发现其多数"配置项"在我方**当前协议与数据模型下无法诚实实现**——不是缺 UI，而是缺字段/缺协议键/缺接口。本节记录这些差异，**结论是"暂不照抄"，待条件具备后再评估**，避免把 UI 做成假开关。

| 序 | 竞品能力 | 我方现状（已核实） | 阻碍 | 建议 |
|---|---|---|---|---|
| 1 | **存储信息**：SD 卡名称/状态/已用容量/格式化/循环录像/最早录像时间/已录制时长 | 设备模型与 IDP 协议**均无任何磁盘字段**；平台侧只有 `disk_full` 告警类型（由服务端录像失败触发，与设备 TF 卡无关） | ① 设备侧需先有 `hal_storage` 上报契约；② **TF/Flash 选型未冻结**（见 §2.3），容量与是否支持循环录像无法确定 | **暂不实现**。待 §2.3 Flash 选型冻结、`hal_storage` 查询契约（容量/已用/健康度）定稿后再补；届时同时补一条设备侧磁盘告警源 |
| 2 | **平台接入**：TUMS 云接入、国标 SIP 参数（SIP 服务器/端口/域/传输模式） | SIP 参数属**设备端配置**，IDP 协议无对应键；TUMS 是竞品自有云，无对应物 | 我方已定"不做云对云"（§2.1 接入总原则） | **不照抄**。国标 SIP 参数由设备/固件侧本地或 profile 配置，平台不下发 |
| 3 | **FTP 设置**（上传服务器/端口/账号/目录） | 无此能力、无此键、无此技能清单项 | 需求本身未进入 PRD | **不实现**，如确有需求另立 PRD 条目 |
| 4 | **OSD 可拖拽定位**（画面上拖动通道名/时间的位置与字号） | 固件仅有 `osd.channelName.enable` / `osd.time.enable` **两个布尔值**，**无位置/字号字段** | 需要 `hal_osd` 增加位置与字号参数，并扩展 IDP `cfg.*` 键集 | **暂不实现**。可先做"开启/关闭"（已实现）；拖拽定位待 `hal_osd` 扩参后单独立项 |
| 5 | **编码参数动态上限**（分辨率/码率上限随设备型号变化） | 固件规则为 `64..max_w`，**上限来自设备 profile**；平台侧 `cfgKeys` 回读时**不返回上下限**，前端当前硬编码 ✅ 已修正为"只标区间提示、不擅自夹取数值"——越界就地标红并拦住下发，避免用户改了值却被静默夹走 | 需新增一次"查询设备能力/限制"的往返（协议工作） | **短期**保持"越界拦截"；**中期**在 IDP 增加 `cfg.limits` 或让 `cfg.get` 一并返回规则表，前端据此渲染真实区间 |
| 6 | **固件在线升级** | PRD 有 MGR-10，但**无任何接口**（`/devices/:id/upgrade` 不存在），设备侧 OTA 仅 `mock_state/ota_state.txt` 占位 | 需要 OTA 通道 + 版本比对 + 分批灰度设计 | **暂不实现**，按 PRD MGR-10 单独立项 |
| 7 | **设备凭据/口令更新** | 拆成两类：**(a) 自研设备本地账户口令**（`localUser.password`，接入规范 §5.7 的 cfg 最小集）——平台统一改密**已实现**（`POST /devices/password`，单台与批量共用）；该键列为**只写键**：可下发、不回显（设备只回空串）、不进 `cfg.data`（因此不会被并进通用「保存并下发」）、平台不落库、审计只记动作不记值、模拟器命令日志对该键脱敏、固件侧不落盘也不进 `cfg_dump_json`。**(b) 第三方设备凭据更新**（ONVIF/RTSP 用户名密码、GB28181 密码、IDP 验证码，即 PRD MGR-04）——`CredentialsEnc` 只在添加设备时写入，`router.go` 仍无对应路由 | (a) 无；(b) 需定义"下发新凭据 + 校验生效 + 失败回滚"三段语义，并决定是否复用同一条下发通道 | (a) **已完成**（提交 b90dea4 补齐 `localUserChanged` 状态回报，统一改密随该轮实现）；(b) **暂不实现**，与 MGR-04 一并设计 |
| 8 | **定时重启的协议归属** | 四条 adapter 均已实现 `Reboot()`：IDP → `cmd.reboot`；GB28181 → `DeviceControl/TeleBoot`；ONVIF → `SystemReboot`；RTSP → 返回 `EForbid`（无重启通道）。故 `supportsReboot()` 对 `rtsp` 恒为 false，对声明了能力清单的 `idp` 设备以 `reboot` 能力位判定，`gb28181`/`onvif` 默认放行 | 无 | **无需额外工作**。前端 `canReboot` 与后端 `supportsReboot` 同构；缺少能力位时按钮/开关灰显，避免点下去才撞 403 |
| 9 | **配置键覆盖差异** | 三处键集合已逐字对齐（已脚本核对）：平台 `cfgKeys` **33 键** = 模拟器 `cfgRules` **33 键**，固件 `register_common_rules()` 的 26 个静态键全部在内，差额恰为按 pattern 展开的 `video.<ch>.<profile>.*` 7 键；`record.channel` **已包含**（旧记录说“未包含”已过时） | 无 | **保持**；新增协议键必须三处同步（键名写错只会进 `rejected[]`，表现为“保存成功但没生效”） |
| 10 | **配置项语义差异**：`image.flip` 与 `image.mirror` 是两个独立布尔，竞品是四选一"旋转" | 我方按固件原样暴露两个开关（关闭/水平/上下/水平+上下） | 无 | **保持**。前端已在"画面信息"页签合并为一个下拉，语义仍映射到两个布尔 |

**已落地部分**（不在待决策范围）：① 远程配置读写与回读确认（33 键）；② 画面预览；③ 配置子页签分屏；④ 越界本地拦截；⑤ 定时重启（IDP）；⑥ 立即重启；⑦ **统一改密**（设备本地账户口令，单台与批量共用 `POST /devices/password`，只写键语义）；⑧ 默认口令未改的设备标黄提示（`hello.localUserChanged`）。
