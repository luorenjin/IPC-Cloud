## Global Constraints（每个任务都受约束）

1. **诚信优先**：任何控件点击后必须产生真实后端效果或处于明确禁用态并说明原因；禁止只弹 toast 冒充成功；禁止示例值 / `'---'` / `'默认'` 兜底，空值一律 `—`。
2. **设计令牌**：颜色只用 `assets/css/main.css` 的 token（`text-ink/body/muted/placeholder`、`bg-surface/surface-2/canvas/zone`、`border-line/line-soft`、`primary/success/warning/danger/info`、`src-idp/src-gb/src-onvif/src-rtsp`、`rec-timer/rec-event/rec-manual`）；圆角只用 `rounded-chrome`（可点击外壳）/ `rounded-signal`（数据面）；不加渐变装饰、不加 eyebrow、不加全大写标签、不在链接尾加「→」；等宽字体只用于 IP/MAC/ID/时间戳/码率。
3. **协议来源字面值** `idp` / `gb28181` / `onvif` / `rtsp` 保持不变，展示名与颜色只从 `utils/enums.ts` 的 `SOURCE_MAP` 取（Task 7 之后）。
4. **i18n**：Task 13 之后新增或重做的页面文案一律 `t('页面.区块.用途')`，词条写入 `locales/zh-CN/*.ts` 与 `locales/en/*.ts`；Task 13 之前的任务保持现有中文硬编码风格即可，不要半接入。
5. **可访问性**：可点击元素必须是 `<button>` / `<a>` / `<NuxtLink>`；纯图标按钮必须有 `aria-label`；不得写 `outline-none` 而不补 `focus-visible` 样式。
6. **数据流**：REST 一律走 `useApi`；失败一律 `toastApiError(e, '兜底文案')`；不得写空 `catch {}` 吞错后继续提示成功。
7. **文案**：中文、句式简洁、动词统一（确定 / 取消 / 保存 / 删除 / 创建 / 添加 / 刷新）；错误 = 原因 + 建议；空状态给下一步动作。
8. **验证**：每个任务至少 `cd platform/web && npm run build` 通过（服务端任务另加 `cd platform/server && go build ./... && go test ./...`）；涉及运行时行为的任务，用 `PORT=3001 npm run dev`（后端在 Docker `localhost:8080`，simulator 已运行）在浏览器实际走一遍并在报告中写明看到了什么；无法在浏览器验证的须在报告里明说。
9. **提交**：每个任务独立提交，信息格式 `type(web|platform): 中文摘要（编号）`，正文列改动点；不 push。
10. **注释**：删除所触及文件中所有「严格对齐图 N」「100% 还原」「商云原型」类注释；新注释描述设计意图而非抄图。
