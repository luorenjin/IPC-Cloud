## Global Constraints（每个任务都受约束）

1. **双向契约一致性**（`AGENTS.md` §5）：涉及配置键名/类型/取值范围的改动，必须在 `firmware/core/src/config.c`（只读参考，本次不改固件）、`simulator/idp/config.go`、`platform/server/internal/api/devices.go` 三处逐字对齐；键名写错不会报错，只会静默进 `cfg.set` 的 `rejected` 列表，表现为"保存成功但没生效"的假成功——每新增一个键必须实测一次读写闭环，不能只凭代码走读判断正确。
2. **不静默钳制、不假成功**：数字越界值保持可见的错误态，不偷偷改成边界值；任何按钮点击后必须产生真实后端效果或处于明确禁用态并说明原因；空值统一 `—`。
3. **校验与保存按分组隔离**：这是本次阶段 1 的核心修复目标（本 spec 问题④）——任何新增分组/字段都必须落在对应分组的独立校验范围内，不得再引入"跨分组全局校验"。
4. **i18n**：新增/改动文案一律 `t('device.config.xxx')`，词条同时写入 `platform/web/locales/zh-CN/device.ts` 与 `platform/web/locales/en/device.ts`；改完在 `platform/web` 目录跑 `python scripts/i18n-check.py` 必须 0 错误（无缺失翻译、无重复键、无死键）。
5. **危险操作二次确认**：恢复出厂设置等破坏性操作必须走 `confirmBox.ask` 的 `inputConfirm`（输入设备名确认）模式，镜像 `askDeleteDevice`（`platform/web/pages/devices/[id].vue:473-484`）的既有实现，不能只是一个 `window.confirm` 或普通对话框。
6. **权限层级不擅自提升**：新增 API 端点权限层级沿用 `requirePerm("config")`（与 `GET/PUT /devices/:id/config`、`POST /devices/:id/reboot` 一致），不要因为"看起来危险"就擅自改成 `"delete"`（本 spec 风险与回滚点 §3 已说明理由）。
7. **验证**：每个任务至少 `cd platform/web && npm run build`（涉及后端/模拟器的任务另加 `cd platform/server && go build ./... && go test ./...` 与 `cd simulator && go build ./...`）；涉及运行时行为的任务，须配合 `simulator -mode=idp` 起模拟设备实际走一遍并在报告中写明看到了什么；无法在浏览器验证的须在报告里明说。
8. **提交**：每个任务独立提交，信息格式 `type(web|platform|simulator): 中文摘要（阶段N-任务M）`，正文列改动点；不 push。
9. **注释**：新注释描述设计意图（为什么这样分组/为什么需要强确认），不描述"做了什么"（代码本身已说明）。

### Task 4: 恢复出厂设置全链路

**文件**：`simulator/idp/config.go`、`simulator/idp/device.go`、`platform/server/internal/adapter/idp/media.go`、`platform/server/internal/api/devices.go`、`platform/server/internal/api/router.go`、`platform/web/pages/devices/[id].vue`

**改动**

1. `simulator/idp/config.go` 新增函数：
   ```go
   // cfgReset 恢复出厂设置：清空当前配置并重置为出厂默认值，
   // 对齐固件 cfg_reset(keep_keys, n) 的语义（firmware/core/src/config.c:594-614）。
   func (d *Device) cfgReset() {
       d.mu.Lock()
       defer d.mu.Unlock()
       d.cfg = cfgDefaults()
   }
   ```
2. `simulator/idp/device.go` 的 `onMessage` 分发（210-266 行区间）新增 `case "cfg.reset":`，与现有 `case "cfg.get":`/`case "cfg.set":`（250-263 行）并列，**照抄 `case "cmd.reboot":`（219-224 行）的回包+延时重连模式**（恢复出厂设置隐含设备重启，行为应与 `cmd.reboot` 一致）：
   ```go
   case "cfg.reset":
       d.cfgReset()
       d.ack(env, 0, "", map[string]any{})
       go func() {
           time.Sleep(time.Second)
           d.hello()
       }()
   ```
3. `platform/server/internal/adapter/idp/media.go` 新增方法，紧邻现有 `ConfigGet`/`ConfigSet`（约 100-180 行区间）——**签名对齐 `ConfigGet`/`ConfigSet` 既有惯例（不接 `context.Context`），不要对齐 `Reboot` 的签名**（`Reboot(ctx context.Context, deviceID string) error` 是 `cmd` 组方法的惯例，`cfg` 组的 `ConfigGet`/`ConfigSet` 均不接 ctx，`ConfigReset` 属于 `cfg` 组，应跟随后者）：
   ```go
   // ConfigReset 恢复出厂设置。
   func (a *Adapter) ConfigReset(deviceID string) error {
       _, err := a.request(deviceID, "cfg", "cfg.reset", map[string]any{})
       return err
   }
   ```
4. `platform/server/internal/api/devices.go` 新增 `handleDeviceConfigReset`，紧邻 `handleDeviceConfigGet`/`handleDeviceConfigSet`（513-574 行区间）——**严格照抄这两个既有 handler 的适配器获取/校验模式**（`adapter.Get("idp").(interface{ ... })` 类型断言 + `toAppErr(err)`，`devices.go:513-541`），不要引入新的错误处理路径；确认名校验镜像 `handleDeleteDevice`（`devices.go:226-246`）：
   ```go
   // handleDeviceConfigReset 恢复出厂设置：清除设备本地配置并重启，需输入设备名二次确认
   // （镜像 handleDeleteDevice 的确认模式）。
   func handleDeviceConfigReset(c *gin.Context) {
       id := c.Param("id")
       var req struct {
           ConfirmName string `json:"confirmName" binding:"required"`
       }
       if err := c.ShouldBindJSON(&req); err != nil {
           fail(c, errs.EBadRequest)
           return
       }
       var d models.Device
       if store.DB.First(&d, "id = ? AND deleted_at = 0", id).Error != nil {
           fail(c, errs.ENotFound)
           return
       }
       if d.Source != "idp" {
           fail(c, errs.EForbid.WithMsg("该设备不支持远程配置"))
           return
       }
       if d.Name != req.ConfirmName {
           fail(c, errs.EBadRequest.WithMsg("设备名不一致"))
           return
       }
       a, okk := adapter.Get("idp").(interface {
           ConfigReset(deviceID string) error
       })
       if !okk {
           fail(c, errs.EForbid.WithMsg("IDP 适配器未就绪"))
           return
       }
       if err := a.ConfigReset(id); err != nil {
           fail(c, toAppErr(err))
           return
       }
       ok(c, nil)
   }
   ```
   （`errs` 只有 `EBadRequest`/`EForbid`/`ENotFound` 等既有常量，没有 `EInternal`；适配器错误统一走 `toAppErr(err)` 转换，不要发明新的错误码或新的错误处理分支。`ConfigReset` 方法签名与 `ConfigGet(deviceID string, keys []string)`/`ConfigSet(deviceID string, values map[string]any)` 保持一致风格——只接 `deviceID string`，不接 `context.Context`，因为 `media.go` 里 `ConfigGet`/`ConfigSet` 均未接收 context 参数，`ConfigReset` 应对齐这一既有惯例而不是自行引入 context。）
5. `platform/server/internal/api/router.go` 新增路由，紧邻现有 `/devices/:id/config` 两条（`router.go:77-78`）：
   ```go
   v1.POST("/devices/:id/config/reset", AuthMiddleware(), requireProjectID(), requirePerm("config"), handleDeviceConfigReset)
   ```
6. 前端 `[id].vue`：Task 1 留下的"恢复出厂设置"占位交互（`toast.info('恢复出厂设置接口即将上线')`）改为真实调用 `api.post('/devices/${devId}/config/reset', { confirmName })`；成功后 `toast.success(...)` 并重新 `loadCfg()` 刷新面板（配置已被清空为出厂默认值）；失败走 `toastApiError`。
