# 本机控制台真实接线（P0 + P1）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `firmware/web` 控制台里**每个可见功能都在 GK7205V200 真机上真实可用**：登录/改密/保存走设备接口，设备做不到的页面按能力开关隐藏。

**Architecture:** 后端（`modules/console`）补齐四类能力（features 如实上报、出厂清凭据、系统时间/设备名/日志端点、网络与 NTP 应用），全部经 HAL 或 `core/config`，不在 console 里写平台代码；前端把 `IPC.api` 作为唯一出口，页面进入时 GET、保存时 PUT，并由 `saveRow` 等待结果再提示。真机验收用 `firmware/tools/board.py` + Python playwright（系统 Chrome）。

**Tech Stack:** C11 + CMake（MSVC mock 单测 / Docker 交叉编译 ARM）；原生 JS（无构建、无 npm）；busybox `ntpd`/`udhcpc`/`ifconfig`；Python 3 + pyserial + playwright。

**Spec:** 本计划依据会话内确认的盘点结论与用户决定（2026-09-27）：
- P0：激活/登录/退出/改密接真；保存等待设备结果；设备信息/状态/网络/存储显示真实值；重启/恢复出厂接真；features 如实上报；修 4 个前端小 bug。
- P1：网络设置（DHCP/静态）真正应用；NTP 与手动校时；设备名称；系统日志查看与导出。
- 决定：做不到的页面**按能力开关隐藏**；恢复出厂**清除管理员凭据、回到未激活**；真机测试密码 **Admin@12345**。

## Global Constraints

- 全中文：UI 文案、错误信息、注释、提交信息（技术名词保持原样）。串口输出的 shell 脚本用英文（避免串口 GBK 乱码）。
- 分层门禁：`core/`、`modules/`（含生成的 `console_assets.c`）禁止 `#include "platform/..."` 与芯片宏 `PLATFORM_|GK7205|RV1106|HI35`；前端文案不得出现 `GK7205`。
- 平台差异只进 `platform/<soc>/`，经 `hal_ops_t` 暴露；新 HAL 能力置 NULL 表示不支持。
- 改 `firmware/web/**` 后必须 `python firmware/scripts/gen_assets.py firmware/web firmware/modules/console/console_assets.c`，生成物一起提交，禁止手改。
- 前端无构建、无 npm、无 CDN；只用原生 JS。
- 远程配置键三处对齐：新增/改名 cfg 键须同步 `platform/server/internal/api/devices.go` 的 `cfgKeys`、`simulator/idp/config.go` 的 `cfgRules`/`cfgDefaults`（本计划新增 `device.name`，需同步）。
- 测试门禁：`ctest --test-dir firmware/build-msvc -C Debug` 全过；`hal_conformance` fail 数不得高于基线。
- 板端 shell 脚本保持 LF（`firmware/.gitattributes` 已覆盖 `docker/rootfs-overlay/**`）。
- 局域网 http 不是安全上下文，**不能用 WebCrypto**；PBKDF2/HMAC-SHA256 用纯 JS 实现并用 RFC 向量自测。

## Review Focus

1. **会话过期 / 设备重启后会话全失**：任何 API 返回 401（code -101）时，前端必须回到登录页而不是弹「请求失败」或假装成功——在 Task 5 的 `IPC.api` 里统一处理并由浏览器用例覆盖（Task 10）。
2. **改静态 IP 把自己改失联**：保存网络设置后浏览器连着旧地址；前端必须提示新地址并在确认后跳转，后端必须先回响应再应用（延后动作）——Task 8 覆盖。
3. **大小写与编码**：proof 必须小写 hex、HMAC 消息是 nonce 的 ASCII 串、口令按 UTF-8 编码（含中文口令）——Task 4 用 C 侧 `console_auth_make_proof` 生成的向量校验 JS 实现。
4. **锁定后的提示**：连续 5 次错误口令后返回 409（-3），前端必须显示「尝试过多，请 N 秒后再试」而不是「密码错误」——Task 5 覆盖。
5. **恢复出厂后仍持有旧 cookie**：出厂后设备回到未激活，浏览器刷新必须进入激活页而非登录页——Task 3 后端 + Task 10 浏览器用例覆盖。

```c
hal_err_t console_auth_wipe(void)
{
    hal_err_t rc = HAL_OK;

    sessions_clear();
    nonces_clear();
    if (crypto_store_available()) {
        /* secure_delete 对不存在的键返回 HAL_ENODEV，视为已清除 */
        if (hal()->crypto->secure_delete) {
            hal_err_t d = hal()->crypto->secure_delete(HAL_SEC_KEY_LOCAL_USER);
            if (d != HAL_OK && d != HAL_ENODEV) rc = HAL_EIO;
        }
    } else if (remove(console_auth_cred_path()) != 0 && errno != ENOENT) {
        rc = HAL_EIO;
    }
    secure_wipe(&s_cred, sizeof(s_cred));
    s_cred_loaded = true;            /* 已知"无凭据"，不必再读存储 */
    s_cred_load_rc = HAL_ENODEV;     /* activation_gate 据此判定为可激活 */
    return rc;
}
```

### Task 4: 纯 JS 密码学（SHA-256 / HMAC / PBKDF2）

**Files:**
- Create: `firmware/web/js/crypto.js`
- Modify: `firmware/web/index.html`（在 `js/core.js` 之前加 `<script src="js/crypto.js"></script>`）
- Test: 浏览器内自测 `IPC.crypto.selfTest()` + Node 离线跑（仅开发机，Node 已装）

**Interfaces:**
- Produces（挂在 `window.IPCCrypto`，core.js 再挂到 `IPC.crypto`）：
  - `utf8(str) -> Uint8Array`
  - `hex(bytes) -> string`（小写）、`unhex(str) -> Uint8Array`
  - `sha256(bytes) -> Uint8Array(32)`
  - `hmac(keyBytes, msgBytes) -> Uint8Array(32)`
  - `pbkdf2(pwdBytes, saltBytes, iter, len) -> Uint8Array`
  - `xor(a, b) -> Uint8Array`
