## Global Constraints（每个任务都受约束）

1. **契约一致性**（`AGENTS.md` §5）：配置键的键名/类型/取值范围必须在
   `firmware/core/src/config.c`（规则表）、`simulator/idp/config.go`、`platform/server/internal/api/devices.go`
   的 `cfgKeys` 三处逐字对齐。键名写错不会报错，只会静默进 `cfg.set` 的 `rejected`——
   **每新增一个键必须实测一次"写入生效 + 越界被拒"闭环**，不能只凭代码走读判断正确。
2. **不静默钳制、不假成功**：数字越界值保持可见错误态；按钮点击必须产生真实后端效果，
   或处于明确禁用态并**说明原因**；空值统一 `—`，不编造。
3. **校验与保存按分组隔离**（上一轮问题④的修复，不得回退）：越界拦截只认当前子页签。
   本轮的**依赖禁用字段一律不参与**越界计算（本 spec D2）——禁用后用户看不到越界提示，
   再让它拦住保存就是"看不见的红点 + 保存变灰"的故障观感。
4. **i18n**：新增/改动文案一律 `t('device.config.xxx')`，词条同时写入
   `platform/web/locales/zh-CN/device.ts` 与 `platform/web/locales/en/device.ts`；
   改完在 `platform/web` 目录跑 `python scripts/i18n-check.py` 必须 0 错误。
   模板里禁止拼键名（脚本只能静态识别字面量）。
5. **危险操作二次确认**：网络设置保存走 `confirmBox.ask({ danger: true })`（说明可能失联）；
   恢复出厂设置继续沿用 `inputConfirm` 输入设备名的既有实现，不得降级为普通对话框。
6. **权限层级与端点不擅自变更**：本轮不新增 API 端点；网络与区域都复用
   `PUT /devices/:id/config` 与 `requirePerm("config")`。
7. **组件抽取不改变行为**：Task 1 的重复渲染合并属**重构**，必须先保证行为等价（含越界提示、
   拒绝提示、区间提示、`supported` 过滤、`advanced` 折叠），再叠加新能力。
8. **验证**：每个任务至少 `cd platform/web && npm run build`（注意该命令**不含类型检查**）；
   涉及后端/模拟器的任务另加 `cd platform/server && go build ./... && go test ./...`
   与 `cd simulator && go build ./...`；涉及固件的任务另加 CMake 构建 + `ctest`
   （`tests/hal_conformance` fail 必须为 0）；涉及运行时行为的任务须在 `:3000`
   （`cd platform && docker compose up -d --build web`）实际走一遍并在报告中写明看到了什么。
9. **提交**：每个任务独立提交，信息格式 `type(web|platform|simulator|firmware): 中文摘要（打磨-任务N）`，
   正文列改动点；不 push。
10. **注释**：新注释描述设计意图（为什么这样分组、为什么必须强确认、为什么禁用字段不参与校验），
    不描述"做了什么"。

### Task 2: 脏值跟踪 + 离开确认 + 保存后回读反馈

**文件**：`platform/web/pages/devices/[id].vue`、`platform/web/locales/zh-CN/device.ts`、`platform/web/locales/en/device.ts`

**改动**

1. `cfg`（`[id].vue:285`）新增 `snapshot: string`、`phase: 'idle' | 'sending' | 'rereading'`；
   `saving: boolean` 保留为计算属性或改由 `phase !== 'idle'` 派生（不要两处状态并存）。
2. `loadCfg`（`[id].vue:534`）成功后写入 `cfg.snapshot = JSON.stringify(cfg.data)`。
3. `isCfgDirty = computed(() => JSON.stringify(cfg.data) !== cfg.snapshot)`。
   注释说明：键序稳定（整体替换对象 + 只改已有键的值），改回原值即视为不脏。
4. 保存按钮（`[id].vue:1199`）`:disabled` 追加 `!isCfgDirty`；旁边新增"有未保存的修改"徽标
   （`device.config.unsaved`），仅脏值时显示。
5. 「重新回读」按钮在脏值时先 `confirmBox.ask`（非 danger，确认文案说明会丢弃未保存修改）再执行。
6. 离开拦截：
   - `onBeforeRouteLeave`：脏值时 `return await confirmBox.ask(...)`（返回 `false` 取消导航）。
   - `window.beforeunload`：脏值时 `e.preventDefault()`；`onUnmounted` 移除监听。
   - 外层五 Tab 切换（`tab` 变量）与子页签切换**不拦截**——配置数据在 `cfg.data` 里跨页签存活，
     切页签不会丢修改，此时弹确认是噪音。注释里写明这个判断依据。
7. 保存流程改为 `sending → rereading → idle`：`PUT` 成功后置 `rereading`、显示
   `device.config.rereading`（「已下发，正在回读设备…」），5 秒后 `loadCfg()` 完成再回 `idle`；
   失败直接回 `idle` + `toastApiError`。定时器存变量并在 `onUnmounted` 清理。
8. 保存按钮 `:loading="cfg.phase !== 'idle'"`。

**验证**：`npm run build` + `i18n-check`；`:3000`：
不动任何字段时保存按钮为禁用；改一个值（如亮度）后出现「有未保存的修改」且保存可用；
点「重新回读」弹出确认；点保存后出现「已下发，正在回读设备…」，约 5 秒后表单刷新且脏值徽标消失；
改一个值后点「返回」到设备列表，确认被拦截；改一个值后按 F5，确认浏览器弹出离开确认；
在「画面信息」改值后切到「移动侦测」再切回，确认值仍在且**没有**弹任何确认。

## 阶段 3 · 移动侦测区域框选

### Task 6: 模拟器 JSON 类型与 `alarm.motion.regions` 契约

**文件**：`simulator/idp/config.go`、`platform/server/internal/api/devices.go`

**改动**

1. `simulator/idp/config.go`：`cfgType` 新增 `cfgJSON`；`cfgRules` 增
   `"alarm.motion.regions": {t: cfgJSON}`；`cfgDefaults()` 增 `"alarm.motion.regions": []`。
2. `coerceCfg` 增 `cfgJSON` 分支，校验规则（对齐固件"类型不符直接拒绝、不做就地转换"的语义）：
   - 只接受数组；元素必须为**长度 4 的数值数组**；四个数均为 `0 ≤ v ≤ 1`；数组长度 ≤ 4；
   - 任一不满足 → 返回 `nil, false`（进 `rejected`）；
   - 通过后按归一化值**保留 3 位小数**存储，避免浮点噪声。

   这条路径为"已核对、无需改动"，避免后人误以为漏了固件。
