## 三、设计评估（frontend-design 视角）

「值守台」令牌体系**本身是好的**，应保留、不推翻：

- ✅ 深色控制室基调**由主题决定**（与视频画面共存、长时间值守不刺眼），不是套用流行深色模板；
- ✅ 信号青 `#00b8c9` 呼应"视频信号"而非任意品牌色，规避了 AI 设计常见的暖陶土/酸性绿默认色；
- ✅ **双圆角有语义分工**（chrome 6px 用于可点击外壳 / signal 2px 用于数据面），不是所有元素一个圆角；
- ✅ 深底用**描边 + 内部高光**表达层级而非千篇一律的灰色阴影；
- ✅ 等宽字体**约束为只用于真正的技术数值**（IP/MAC/ID/码率/时间戳），而非当作小标签装饰。

**待改进的设计问题**（而非令牌问题）：

1. **首页信息层级倒置**：弧形量规占据视觉焦点，但值班员真正要看的是"哪台离线了、刚才报了什么警"。量规是"一个大数字 + 小标签"的默认套路变体，应让实时告警流成为主角。
2. **功能入口面板是纯冗余**：与侧栏 1:1 重复，占掉首屏面积却不提供新信息。按 Chanel 原则，这是应当摘掉的那件配饰。
3. **焦点态缺失是设计缺陷**，不只是 a11y 合规问题：控制室场景下值班员大量使用键盘，看不见焦点即不可用。
4. **空态未被当作设计对象**：Skeleton 近乎缺席，多数页面加载中为空白。

## 四、改进计划（六阶段，按序执行）

> 沿用上轮已批准的执行约束：**前端为主 + 只修前后端断链**；**i18n 先隐藏语言切换**；**一次审批、按阶段顺序执行**；**每阶段末汇报验证结果**。

### 阶段 1 · 崩溃与正确性修复（后端小改，≈1 人日）

**必须最先做——A-1 是线上 panic。**

1. `rtsp.go:153` 改为先判 `ok` 再取 `err.Error()`，消除 nil 求值。
2. `scheduler.go:46-52` 修正索引：`for i := 1; i < len(nodes); i++`。
3. `nodes.go` `selfCheckNode` 返回并持久化失败 `reason`（ACC-02）。
4. `devices.go` `handleExportDevices` 接入与列表页一致的筛选条件（MGR-13）。
5. `engine.go` 实现 `taskProgress`：将 `bus` 事件写入任务记录，供 `/tasks` 返回。

**验证**：`go build ./... && go test ./...`；RTSP 设备诊断走一遍不崩；两节点环境确认第二个节点会被调度到。

### 阶段 2 · 共享原语（前端，≈2 人日，后续阶段硬前置）

1. 新建 `utils/format.ts`：`fmtTime` / `ago` / `dash` / `DAY_NAMES` / `fmtSchedule`，替换 5+3+2 处重复实现。
2. 新建 `utils/enums.ts`：`SOURCE_MAP`（四个协议字面值的展示名 + 令牌色，**唯一权威来源**）、`ALARM_KIND_MAP`、`STATUS_MAP`，消除「人工同步」注释。
3. `useWs` 重构为**单连接多订阅**：模块级单例连接 + 订阅者集合，解决 E-2。
4. 新建 `useForm` + `UiField`：字段级内联错误（E-4）。

**验证**：`npm run build`；grep 确认重复实现归零。

### 阶段 3 · 可访问性与响应式基线（前端，≈2.5 人日）

1. **19 个 ui 组件补 `focus-visible` 环**（信号青 1px + 2px offset），与 `outline-none` 配对；`main.css` 加 `prefers-reduced-motion` 兜底。
2. `<div @click>` 全部改为 `<button>` / `<NuxtLink>`；纯图标按钮补 `aria-label`。
3. **删除 6 处 `w-55`/`w-58`/`h-13` 幽灵类**，改用 Tailwind v4 `@theme` 自定义尺寸令牌，消除 inline style 兜底。
4. 侧栏三档折叠（展开 220 / 图标 56 / 移动抽屉）；通道树窄屏可收起。

**验证**：`npm run build`；键盘 Tab 走完主流程焦点全程可见；375px / 768px / 1440px 三档实测。

### 阶段 4 · 后端已就绪功能的前端接入（≈4 人日）

按"后端零改动即可点亮"排序，性价比最高：

1. **ALM-05 告警策略页**（`/alarm-policies`，engine 已消费，缺整页）。
2. **ADD-06/07 ONVIF 发现 + ONVIF/RTSP 手动添加**（并入添加设备弹窗）。
3. **ADD-05 国标白名单**三端点接入。
4. **MGR-12 设备转移** + **ACC-04 分组移动设备**。
5. **REC-07 存储概览**卡片 + **P-18 任务中心**拉 `/tasks`（依赖阶段 1 第 5 项）。

**验证**：每项在浏览器实走一遍并记录所见；配合 `simulator` 联调 ONVIF/RTSP。

### 阶段 5 · 首页重做与三态补齐（≈2.5 人日）

1. **首页信息层级重排**：实时告警流升为主角，在线率降为紧凑指示条；**删除功能入口 7 面板**与顶栏「返回首页」（F-3）。
2. `loadNames` 改为按需查询，不再全量拉 `/devices`+`/channels`（F-4）。
3. **分页补齐**：角色/成员/节点/计划/模板五处接 `UiPagination`（E-3）。
4. **Skeleton / 空态 / 错误态三件套补齐**；空态给下一步动作而非只写"暂无数据"。
5. 清理 19 处 `catch {}`：区分"可忽略"（加注释说明）与"必须提示"（改 `toastApiError`）。
6. **设备列表 / 设备详情 / 直播通道树接入 WS 实时状态**（E-1，依赖阶段 2 第 3 项）。

**验证**：`npm run build`；断网模拟错误态；simulator 上下线看列表实时变化。

### 阶段 6 · i18n 全量接入（≈5 人日，**建议单独审批**）

1. 拆出 `locales/zh-CN/*.ts` 与 `locales/en/*.ts`，键约定 `页面.区块.用途`。
2. 20 页文案全量走 `t()`；**完成后才恢复语言切换入口**（此前保持隐藏）。

**验证**：切 EN 后全站无残留中文；切回 zh-CN 无缺键。
