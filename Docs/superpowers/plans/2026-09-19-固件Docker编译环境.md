# 固件 Docker 编译环境 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 Docker 把国科微（GOKE）IPC Linux SDK（基线 `GKIPCLinuxV100R001C00SPC030` + 累积补丁 `SPC031`）的官方编译环境固化下来，让 `gk7202v300`/`gk7205v200`/`gk7205v300`/`gk7605v100` 四款候选芯片配置都能在任意一台 Windows 机器上、不装 Ubuntu/WSL 全局环境的前提下，可重复地编译出 uboot/kernel/rootfs 镜像。

**Architecture:** `firmware/docker/` 下的 `Dockerfile` 构建一个 `ubuntu:18.04` 编译机镜像（内置 GOKE 交叉工具链依赖的 apt 包 + `gosu` 非 root 降权工具），`entrypoint.sh` 在容器启动时按 `BUILD_UID`/`BUILD_GID` 动态建立普通用户并 `chown` 挂载的 SDK 卷后降权执行命令。SDK 源码存放在 Docker **命名卷**（而非 bind mount 宿主目录）里，因为 Windows/NTFS 无法表示 SDK 内 566 个符号链接和可执行位；`Makefile` 把"解包+打补丁"（`sdk-init`）、"按 `CHIP` 编译"（`sdk-build`）、"交互配置/进容器调试"（`sdk-menuconfig`/`sdk-shell`）、"把卷内镜像文件导出到宿主可见目录"（`sdk-export`）、"清理"（`sdk-clean`/`sdk-clean-all`）这几个操作封装成 `docker build`/`docker run -v`/`docker volume` 调用。

**Tech Stack:** Docker Desktop（WSL2 后端）、`ubuntu:18.04` 基础镜像、Bash 脚本、GNU Make（Makefile 驱动命令面，容器内 SDK 自带的 `build/root.mk` 驱动实际编译）、`gosu` 非 root 降权。

**Spec:** [`Docs/superpowers/specs/2026-09-19-固件Docker编译环境-design.md`](../specs/2026-09-19-固件Docker编译环境-design.md)

## Global Constraints

- 基础镜像固定 `ubuntu:18.04`；apt 包精确为：`make gcc bison flex fakeroot gettext bc libncurses5-dev tar gzip unzip file rsync python3 gosu ca-certificates`（前 7 个是 PDF/实测编译+`menuconfig`依赖，后 5 个是 SDK 内部脚本/降权工具/HTTPS 证书需要）。
- SDK 源码包（`.tar.gz`/`.zip`，数百 MB～GB 级）**不进 git**，只通过只读 bind mount（`:ro`）喂给容器；SDK 本体解包后存放在 Docker **命名卷** `goke-sdk-src` 里，不用 bind mount 宿主目录（NTFS 无法表示符号链接/可执行位，见 spec §4.1）。
- 容器内构建用户为动态创建的非 root 用户，UID/GID 通过 `BUILD_UID`/`BUILD_GID` 环境变量传入，默认均为 `1000`；命名卷默认 root 属主，`entrypoint.sh` 必须在降权前先 `chown` 该卷，否则所有写入报 `Permission denied`（本次实测发现，spec 原文未提及，是本计划新增的关键修正）。
- 四款候选芯片配置：`gk7202v300`、`gk7205v200`、`gk7205v300`、`gk7605v100`，对应 SDK 内 `configs/<chip>/<chip>_def_cfg.mk`；`Makefile` 的 `CHIP` 变量默认 `gk7205v200`，可覆盖为其余三款之一；不硬编码单一芯片型号（呼应根 CLAUDE.md「芯片选型未定稿前不得新增芯片假设」的约束）。
- SDK 基线版本固定 `GKIPCLinuxV100R001C00SPC030`，累积补丁固定 `GKIPCLinuxV100R001C00SPC031`（只打这一个补丁，它已合入 CP001/CP002），版本号在脚本里硬编码，不做参数化抽象（YAGNI，等出现第二个 SDK 版本再抽象，spec §7）。
- **Windows 宿主注意事项（本计划范围内新发现，必须遵守）：**
  - 从 Git Bash 执行任何 `docker run -v ...`/`docker build` 命令，前面必须加 `MSYS_NO_PATHCONV=1`，否则 MSYS 会把容器侧的 POSIX 风格路径（如 `/sdk`）错误改写成 Windows 路径。
  - **GnuWin32 `make`（3.81，本机路径 `C:\Program Files (x86)\GnuWin32\bin\make.exe`）读取 `Makefile` 文件本身时，无法正确处理直接写在文件里的中文字符**——无论是变量默认值（如 `SDK_SRC_DIR ?= D:/.../国科微/...`）还是 recipe 里的 `echo "中文提示"`，都会被解析成乱码（本计划实测确认：命令行 `make VAR=值` 传入的中文、环境变量前缀传入的中文、以及容器内 Linux/UTF-8 环境下 bash 脚本里的中文均不受影响，唯独 Makefile 文件本身的中文文本会乱码）。因此：
    - `Makefile` 里所有面向 Windows 终端回显的文字（`$(error ...)`、`sdk-clean-all` 的确认提示）一律用英文。
    - `SDK_SRC_DIR`/`SDK_PATCH_DIR`（宿主上的真实路径含中文 `国科微`）**不设中文默认值**，必须由调用方在命令行显式传入，如 `make sdk-init SDK_SRC_DIR=... SDK_PATCH_DIR=...`。
    - 容器内部脚本（`scripts/*.sh`）不受此限制，中文提示原样保留（跑在容器的 Linux/UTF-8 环境里，`bash` 直接解释执行，不经过 GnuWin32 `make` 解析）。

- [ ] **Step 1: 写 `entrypoint.sh`**

```bash
#!/bin/bash
set -e
BUILD_UID="${BUILD_UID:-1000}"
BUILD_GID="${BUILD_GID:-1000}"
if ! getent group "$BUILD_GID" >/dev/null 2>&1; then
    groupadd -g "$BUILD_GID" builder
fi
if ! getent passwd "$BUILD_UID" >/dev/null 2>&1; then
    useradd -u "$BUILD_UID" -g "$BUILD_GID" -m -s /bin/bash builder
fi
USER_NAME=$(getent passwd "$BUILD_UID" | cut -d: -f1)
if [ -d /sdk ]; then
    chown "$BUILD_UID:$BUILD_GID" /sdk
fi
exec gosu "$USER_NAME" "$@"
```

- [ ] **Step 2: 写 `scripts/sdk-init.sh`**

```bash
#!/bin/bash
set -euo pipefail

SDK_NAME="GKIPCLinuxV100R001C00SPC030"
PATCH_NAME="GKIPCLinuxV100R001C00SPC031"
SDK_DIR="/sdk/${SDK_NAME}"

if [ -f "${SDK_DIR}/Makefile" ] && [ "${FORCE:-0}" != "1" ]; then
    echo "[sdk-init] 已初始化（${SDK_DIR}/Makefile 存在），跳过。如需强制重新初始化，使用 FORCE=1 make sdk-init"
    exit 0
fi

if [ ! -f "/sdk-src/${SDK_NAME}.tar.gz" ]; then
    echo "[sdk-init] 错误：/sdk-src/${SDK_NAME}.tar.gz 不存在，检查 SDK_SRC_DIR 挂载路径是否正确" >&2
    exit 1
fi

if [ ! -f "/sdk-patch/${PATCH_NAME}.zip" ]; then
    echo "[sdk-init] 错误：/sdk-patch/${PATCH_NAME}.zip 不存在，检查 SDK_PATCH_DIR 挂载路径是否正确" >&2
    exit 1
fi

echo "[sdk-init] 清理旧目录（如存在）..."
rm -rf "${SDK_DIR}" /tmp/patch-extract

echo "[sdk-init] 解压 SDK 基线（${SDK_NAME}.tar.gz）..."
tar xzf "/sdk-src/${SDK_NAME}.tar.gz" -C /sdk

echo "[sdk-init] 解压 ${PATCH_NAME} 补丁（双层嵌套 zip）..."
mkdir -p /tmp/patch-extract
cd /tmp/patch-extract
unzip -q "/sdk-patch/${PATCH_NAME}.zip"
unzip -q "${PATCH_NAME}/${PATCH_NAME}.zip" -d .

echo "[sdk-init] 打补丁..."
cd "${PATCH_NAME}"
chmod +x patch_install.sh
./patch_install.sh "${SDK_DIR}"

cd /
rm -rf /tmp/patch-extract

echo "[sdk-init] 完成。SDK 目录：${SDK_DIR}"
ls "${SDK_DIR}"
```

### Task 2: Makefile 命令面与 `sdk-init` 端到端验证

**Files:**
- Create: `firmware/docker/Makefile`

**Interfaces:**

- Produces: Docker 命名卷 `goke-sdk-src`；Makefile 变量 `SDK_SRC_DIR`（无默认值，必须显式传入）、`SDK_PATCH_DIR`（无默认值，必须显式传入）、`CHIP`（默认 `gk7205v200`）、`TARGET`（默认 `clean`）、`BUILD_UID`/`BUILD_GID`（默认均 `1000`）、`FORCE`（默认 `0`）、`OUT_DIR`（默认 `$(CURDIR)/out`）；目标 `image`/`sdk-init`/`sdk-build`/`sdk-menuconfig`/`sdk-shell`/`sdk-export`/`sdk-clean`/`sdk-clean-all`，供 Task 3/4 直接调用，本任务只验证 `image` 与 `sdk-init`。

- [ ] **Step 1: 写完整 `Makefile`**

```makefile
IMAGE_NAME  := goke-sdk-build
SRC_VOLUME  := goke-sdk-src

SDK_SRC_DIR   ?=
SDK_PATCH_DIR ?=
OUT_DIR       ?= $(CURDIR)/out

CHIP       ?= gk7205v200
TARGET     ?= clean
BUILD_UID  ?= 1000
BUILD_GID  ?= 1000
FORCE      ?= 0

DOCKER_RUN := MSYS_NO_PATHCONV=1 docker run --rm \
	-e BUILD_UID=$(BUILD_UID) -e BUILD_GID=$(BUILD_GID) \
	-v $(SRC_VOLUME):/sdk

.PHONY: image sdk-init sdk-build sdk-menuconfig sdk-shell sdk-export sdk-clean sdk-clean-all

image:
	MSYS_NO_PATHCONV=1 docker build -t $(IMAGE_NAME) .

sdk-init: image
ifeq ($(strip $(SDK_SRC_DIR)),)
	$(error SDK_SRC_DIR is not set. Example: make sdk-init SDK_SRC_DIR=/path/to/Software SDK_PATCH_DIR=/path/to/patch)
endif
ifeq ($(strip $(SDK_PATCH_DIR)),)
	$(error SDK_PATCH_DIR is not set. Example: make sdk-init SDK_SRC_DIR=/path/to/Software SDK_PATCH_DIR=/path/to/patch)
endif
	$(DOCKER_RUN) \
		-v "$(SDK_SRC_DIR)":/sdk-src:ro \
		-v "$(SDK_PATCH_DIR)":/sdk-patch:ro \
		-e FORCE=$(FORCE) \
		$(IMAGE_NAME) sdk-init.sh

sdk-build: image
	$(DOCKER_RUN) -e CHIP=$(CHIP) $(IMAGE_NAME) sdk-build.sh

sdk-menuconfig: image
	MSYS_NO_PATHCONV=1 docker run --rm -it \
		-e BUILD_UID=$(BUILD_UID) -e BUILD_GID=$(BUILD_GID) \
		-v $(SRC_VOLUME):/sdk \
		-w /sdk/GKIPCLinuxV100R001C00SPC030 \
		$(IMAGE_NAME) bash -c "cp configs/$(CHIP)/$(CHIP)_def_cfg.mk cfg.mk && source build/env.sh && make menuconfig"

sdk-shell: image
	MSYS_NO_PATHCONV=1 docker run --rm -it \
		-e BUILD_UID=$(BUILD_UID) -e BUILD_GID=$(BUILD_GID) \
		-v $(SRC_VOLUME):/sdk \
		-w /sdk/GKIPCLinuxV100R001C00SPC030 \
		$(IMAGE_NAME) bash

sdk-export: image
	mkdir -p "$(OUT_DIR)"
	$(DOCKER_RUN) -e CHIP=$(CHIP) \
		-v "$(OUT_DIR)":/host-out \
		$(IMAGE_NAME) sdk-export.sh

sdk-clean: image
	$(DOCKER_RUN) -e CHIP=$(CHIP) -e TARGET=$(TARGET) $(IMAGE_NAME) sdk-clean.sh

sdk-clean-all:
	@echo "About to delete volume $(SRC_VOLUME) (all SDK source and build output). This cannot be undone."
	@echo "To confirm, run: docker volume rm $(SRC_VOLUME)"
```

# GOKE IPC Linux SDK Docker 编译环境

用 Docker 固化国科微（GOKE）IPC Linux SDK（基线 `GKIPCLinuxV100R001C00SPC030` + 累积补丁 `SPC031`）的官方编译环境，覆盖四款候选芯片配置：`gk7202v300`/`gk7205v200`/`gk7205v300`/`gk7605v100`。任何一台装了 Docker Desktop 的 Windows 机器都能不装 Ubuntu/WSL 全局环境、可重复地编译出 uboot/kernel/rootfs 镜像。

设计依据：[`Docs/superpowers/specs/2026-09-19-固件Docker编译环境-design.md`](../../Docs/superpowers/specs/2026-09-19-固件Docker编译环境-design.md)。

## 前置条件

- Docker Desktop（WSL2 后端）。
- 原厂 SDK 压缩包 `GKIPCLinuxV100R001C00SPC030.tar.gz` 与累积补丁 `GKIPCLinuxV100R001C00SPC031.zip`（仓库外部资产，不进 git，需自行获取存放路径）。
- 若在 Windows 上用 GnuWin32 `make` 驱动本目录的 `Makefile`：注意其无法正确解析 Makefile 文件里直接写的中文字符（详见下方「已知限制」），因此涉及中文路径的变量一律通过命令行显式传入，不要写进 Makefile 默认值。也可以不装 `make`，直接照抄各目标对应的 `docker build`/`docker run` 命令手动执行。

## 快速开始

```bash
cd firmware/docker

# 1. 构建镜像
MSYS_NO_PATHCONV=1 docker build -t goke-sdk-build .

# 2. 初始化 SDK（把下面两个路径换成你机器上的实际位置）
make sdk-init \
  SDK_SRC_DIR="D:/path/to/GKIPCLinuxV100R001C00SPC030/Software" \
  SDK_PATCH_DIR="D:/path/to/patch"

# 3. 编译指定芯片（CHIP 默认 gk7205v200，可换成 gk7202v300/gk7205v300/gk7605v100）
make sdk-build CHIP=gk7205v200

# 4. 导出镜像到宿主可见目录 firmware/docker/out/<chip>/
make sdk-export CHIP=gk7205v200

# 5. 清理某芯片的编译中间产物
make sdk-clean CHIP=gk7205v200
```

## Makefile 目标一览

| 目标 | 作用 |
|---|---|
| `image` | 构建/更新 Docker 镜像（其余目标均自动依赖它） |
| `sdk-init` | 首次初始化：卷内解压 SDK、打 SPC031 补丁。已初始化则跳过，`FORCE=1` 强制重新初始化 |
| `sdk-build` | 按 `CHIP` 跑 `make build`（uboot+kernel+rootfs 等全部阶段） |
| `sdk-menuconfig` | 交互式 `make menuconfig`（需要 TTY，已用 `docker run -it`） |
| `sdk-shell` | 进容器交互 shell，默认工作目录为 SDK 根目录，可手动跑 `make uboot`/`make linux` 等部分编译命令 |
| `sdk-export` | 把卷内 `out/<chip>/image/` 拷到宿主 `firmware/docker/out/<chip>/` |
| `sdk-clean` | 按 `CHIP` 跑 `make <target>`（`TARGET` 默认 `clean`） |
| `sdk-clean-all` | 打印确认提示，不自动执行；需要手动 `docker volume rm goke-sdk-src` 才会真正删除卷（含全部 SDK 源码与编译产物） |

可覆盖的变量：`CHIP`（默认 `gk7205v200`）、`TARGET`（默认 `clean`）、`BUILD_UID`/`BUILD_GID`（默认均 `1000`）、`FORCE`（默认 `0`）、`OUT_DIR`（默认 `firmware/docker/out`）、`SDK_SRC_DIR`/`SDK_PATCH_DIR`（无默认值，`sdk-init` 时必须显式传入）。

## 已知限制

- 四款候选芯片均完成端到端编译验证，但没有实际开发板可供逐一烧录验证镜像能否真正跑通；本环境止步于"编译产出 image 文件"。
- 若后续候选芯片范围变化（如更换 SDK 基线带来新增配置），需要新增对应的 `configs/<chip>/` 支持，本环境不预先设计。
- `firmware/` 通用层（HAL/core/modules）与本编译环境的对接是独立的后续工作，需等待芯片选型定稿（见根 `CLAUDE.md` 与 `Docs/PRD/决策记录与待定事项.md`）。
- SDK 版本升级（新的 SPCxxx 基线或补丁）需要同步更新 `scripts/*.sh` 里硬编码的 `SDK_NAME`/`PATCH_NAME` 变量。

## 常见故障排查

- **`docker run` 报 `CreateFile ...: The filename ... is incorrect` 或路径出现乱码**：多半是从 Git Bash 执行 `docker` 命令时漏加 `MSYS_NO_PATHCONV=1` 前缀，或者把含中文的路径硬编码进了 `Makefile` 文件本身（GnuWin32 `make` 无法正确解析 Makefile 文件里的中文字符）——把中文路径改成命令行 `VAR=值` 显式传入即可。
- **`sdk-init`/`sdk-build` 报 `Permission denied`**：命名卷默认 root 属主，`entrypoint.sh` 已包含 `chown "$BUILD_UID:$BUILD_GID" /sdk` 修复此问题；若你修改过 `entrypoint.sh` 且重新出现该报错，检查该行是否还在，以及是否在 `gosu` 降权**之前**执行。
- **`make menuconfig` 卡住或报没有终端**：该目标需要交互式 TTY，必须用 `make sdk-menuconfig`（内部已用 `docker run -it`），不要用 `sdk-shell` 里再手动拼 `docker run` 且漏加 `-it`。
- **`sdk-build` 报 `CHIP=... 不是合法配置`**：`CHIP` 必须是 `gk7202v300`/`gk7205v200`/`gk7205v300`/`gk7605v100` 之一，对应 SDK 内 `configs/<chip>/<chip>_def_cfg.mk` 必须存在。
