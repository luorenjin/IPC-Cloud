# 设备配置交互打磨（第三轮）

## 背景（Context）

`platform/web/pages/devices/[id].vue` 的远程配置面板（MGR-09）已在
`Docs/superpowers/specs/2026-09-11-设备远程配置重新设计-design.md` 中完成**结构性**重设计
（七段式 IA、分组独立校验、URL 同步、预览联动、编码预设、重启入口去重、白名单扩展、
`reboot_required` 徽标、恢复出厂设置全链路），对应提交 `d02917b` / `a55df64` / `f20b6b2` /
`65edc95` / `0195d40` / `65bfd2c`。

用户随后的反馈是「完善设备配置，优化UI/UE」——即：结构已经对了，但**交互细节仍不到位**，
且上一轮显式推迟的两个能力（网络字段编辑、移动侦测区域框选）现在要一并补齐。

本文档是第三轮的可执行规格，引用代码行号以 `[id].vue` 当前状态为准。

### 已确认的执行约束（用户逐项选定）

- **范围 = 前端打磨 + 网络字段开放编辑 + 移动侦测区域框选**（即上一轮 spec 的"阶段 3"提前）。
- **四项行为增强全部纳入**：依赖字段联动禁用 / 脏值跟踪 + 离开确认 / 保存后回读反馈 / 时区改为下拉。
- **网络字段按接入规范补齐四件套**：`net.{dhcp,ip,mask,gw,dns}`（不是只加 DNS）。
- **`alarm.motion.regions` 序列化采用元组形式** `[[x,y,w,h], …]`（对齐
  `Docs/PRD/IpcCloud设备接入规范_v1.0.md:308` 的事件 payload 先例），**归一化 0–1，最多 4 个区域**。
- **区域框选以设备抓拍快照作底图**（复用 `POST /channels/:id/snapshot`）。
- **实现架构采用「分层收敛」**：页面只做编排，抽出 3 个组件
  （`ConfigFieldRow.vue` / `NetworkSettings.vue` / `MotionRegionEditor.vue`），状态仍在页面内，
  不引入 Pinia/store。
- **交付形式**：先本 spec + 配套 plan，确认后再实现。

### 与上一轮不同的关键前提

上一轮把固件当作**只读参考**（"本次不改固件"）。本轮**必须改固件的配置规则表**：
`AGENTS.md` §5 的"三处逐字一致"要求 `firmware/core/src/config.c`、
`simulator/idp/config.go`、`platform/server/internal/api/devices.go` 的 `cfgKeys` 在
键名/类型/范围上完全对齐，而 `net.mask` / `net.gw` / `net.dns` 在当前固件规则表里**不存在**
（`firmware/core/src/config.c:293-315` 的 `register_common_rules` 只有 `net.dhcp` / `net.ip`），
不改固件就只能是"平台能选、设备静默拒绝"的假成功。固件改动**限于规则表条目**（不动 HAL、不动业务逻辑）。

## 一、审计结论

### 1.1 做得好、本轮应保留的决策

- **分组独立校验**（`invalidKeysByTab`，`[id].vue:392`）：越界值只拦当前子页签，页签项挂红点——
  上一轮修的"跨页签隔空拦截"没有回退。
- **不静默钳制**（`setCfgNum`，`[id].vue:365`）：越界值原样可见，不偷偷改成边界值。
- **部分成功语义**（`saveCfg`，`[id].vue:569`）：对齐设备侧 `rejected[]`，区分"全部成功"与"部分被拒"。
- **预览为纯展示层叠加**（`previewStyle`，`[id].vue:351`）：CSS `filter`/`transform` 只影响网页预览，
  不改变抓帧机制，也不假装模拟锐化。
- **定时重启计划懒加载 + `immediate`**（`[id].vue:559` 起的 `watch(cfgTab)`）：深链 `?tab=maintain`
  也能正确加载，且 TDZ 已规避。

## 二、设计

### 2.1 组件拆分（方案 A：分层收敛）

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（选定）** | 页面保留状态与编排，抽出 3 个组件 | `[id].vue` 因删除三处重复渲染而**略变短**；新增组件各自内聚，可单独测 |
| B | 全部内联进 `[id].vue` | 文件将达 ~1700 行，拖拽状态机与配置逻辑混杂 |
| C | 整块抽成 `ConfigPanel.vue` | 最干净，但需重排 1000+ 行模板，回归面最大 |

三个新组件（放 `platform/web/components/device/`）：

1. **`ConfigFieldRow.vue`** —— 一个配置字段的整行渲染。当前同一段
   `v-if switch / v-else-if enum / v-else-if int / v-else input` 在模板里出现**三处**
   （主网格 `[id].vue:1063-1090`、高级参数折叠区 `:1099-1140`、画面滑杆行 `:1022-1043` 的孪生逻辑）。
   收敛成一处后，**依赖禁用**、越界提示、拒绝提示只需实现一次。
2. **`NetworkSettings.vue`** —— `net.*` 五键的编辑区 + 独立保存 + 强确认（阶段 2）。
3. **`MotionRegionEditor.vue`** —— 区域框选（阶段 3）。

不在本轮范围：外层的「概览/通道/配置/诊断/日志」五 Tab、`useConfirm`、`useForm`、全局 store。

### 2.2 阶段 1 · 交互正确性（纯前端，不动任何接口）

**1.2.1 依赖字段联动禁用（问题①）**

`CfgField` 新增可选声明（`[id].vue:276`）：

```ts
dependsOn?: { key: string; equals: unknown; hintKey: string }
```

派生出 `cfgFieldDisabledReason(f): string`（空串=可用）；命中的字段：
控件 `:disabled="true"`，并在其后显示 `hintKey` 文案。映射表：

| 字段 | 依赖 | 提示键 |
|---|---|---|
| `alarm.motion.sensitivity` | `alarm.motion.enable === true` | `device.config.dependsMotion` |
| `record.mode` / `record.retention_days` / `record.channel` | `record.enabled === true` | `device.config.dependsRecord` |
| `time.ntp.server` | `time.ntp.enable === true` | `device.config.dependsNtp` |

**关键规则（避免引入新的"隔空拦截"）**：被禁用的字段**不参与** `invalidKeysByTab` 计算。
否则"先改一个越界值 → 再关掉总开关"会让页签红点亮起、保存按钮变灰，而用户看不到任何越界提示
（字段已禁用），表现如系统故障——这正是上一轮问题④的翻版。

语义说明：仅**禁用交互**，不隐藏、不清空——设备侧该键的值仍然存在，只是移动侦测/录像关闭时不会生效。

**1.2.2 脏值跟踪 + 离开确认（问题②）**

- `cfg.snapshot: string`：`loadCfg` 成功后 `JSON.stringify(cfg.data)`。
- `isCfgDirty = computed(() => JSON.stringify(cfg.data) !== cfg.snapshot)`。
  键序稳定（`loadCfg` 整体替换对象、编辑只改已有键的值），故可直接比字符串；
  用户"改回原值"即视为不脏（符合直觉）。
- 「保存并下发」`:disabled` 追加 `!isCfgDirty`；页签内显示「有未保存的修改」徽标。
- 「重新回读」在脏值时先走 `confirmBox.ask`（非 danger）确认丢弃。
- 离开拦截两层：
  - `onBeforeRouteLeave`：脏值时 `return await confirmBox.ask(...)`（vue-router 4 支持返回 `false` 取消导航）。
  - `window.beforeunload`：脏值时 `e.preventDefault()`，`onUnmounted` 移除监听。
- 网络字段（阶段 2）的未保存修改**也计入** `isCfgDirty`（离开拦截要覆盖它），
  但「保存并下发」的可用性只看非网络字段（见 2.3.3）。

**1.2.3 保存后回读反馈（问题③）**

`cfg.saving: boolean` 升级为 `cfg.phase: 'idle' | 'sending' | 'rereading'`：

```
idle --保存--> sending --PUT 成功--> rereading --5s 后 loadCfg 完成--> idle
                        \--失败--> idle + toast
```

- 保存按钮 `:loading="cfg.phase !== 'idle'"`，禁用条件不变。
- `rereading` 期间显示 `device.config.rereading`（「已下发，正在回读设备…」），
  把原本静默的表单自变更变成用户可预期的动作。
- 定时器存于变量并在 `onUnmounted` 清理（避免离开页面后仍触发 `loadCfg`）。

**1.2.4 时区改为下拉（问题④）**

`CfgField` 新增 `type: 'tz'`。渲染为 `UiSelect`，选项 = 内置常见时区表 ∪ 当前值：
当前值是表外值（如设备上报了未收录的时区）时，把它补成第一项、标签用原始字符串，
**保证不因换成下拉而丢失或改写设备已有的值**。

仍然保存为字符串，**不新增枚举约束**——固件侧该键本就是自由字符串，
平台单方面加白名单只会制造"选了却被拒绝"的新问题。

**1.2.5 编码字段排列修复（问题⑤）**

主网格 5 项（GOP/码率控制已在折叠区）是奇数，必然留孤格。解法：让**「编码格式」占满整行**
（`md:col-span-2`），其余 4 项两两成行：

```
[ 编码格式                     ]
[ 画面宽度 ] [ 画面高度 ]
[ 帧率    ] [ 码率(kbps) ]
```

分辨率同排、"帧率/码率"同排，符合用户对"一组参数"的阅读预期。

> 未纳入本轮（需单独确认）：把"画面宽度 / 画面高度"换成「常用分辨率」下拉 + 自定义。
> 它能进一步降低输入成本，但属于新增字段控件语义，不在本次已确认的 10 项清单内，此处仅记录。

**1.2.6 档位 chips 反馈（问题⑥）**

- 「自定义」从 `<span>` 改为**虚线边框、`cursor-default`** 的状态徽标（可选中的按钮与不可点的状态
  在视觉上必须区分开），并保留 `aria-current` 语义。
- 芯片组旁新增提示 `device.config.presetHint`：「档位将同时设置 帧率 / 码率 / GOP（GOP 在下方「高级参数」中）」，
  仅在 `gop` 存在于该组字段时渲染（设备不支持 GOP 时这句提示是错的）。

**1.2.7 设备维护页签整理（问题⑦⑧）**

- 定时重启的段内按钮文案由 `common.save` 改为 `device.config.saveRebootPlan`（「保存定时重启」），
  与页面级「保存并下发」在语义上彻底分开。
- 「恢复出厂设置」危险区块**移到页面级保存栏下方**：破坏性操作不再紧贴常规保存按钮。
- 定时重启的 `UiSwitch` 在 `!canReboot` 时外套 `UiTooltip`（复用 `device.detail.rebootUnsupported`），
  与页头重启按钮同一模式——**禁用必须给出原因**。

**1.2.8 a11y（问题⑨）**

- 红点同时以文本传达：每个页签按钮 `aria-describedby` 指向一个 `sr-only` 说明
  （`device.config.tabHasError`），不依赖颜色。
- 手写 tablist 补键盘行为（roving tabindex）：选中项 `tabindex=0`、其余 `-1`；
  `←/→` 切换、`Home/End` 跳首尾，选中即切换子页签。
- 内容容器补 `role="tabpanel"` + `aria-labelledby`。

**1.2.9 画面信息呈现（问题⑩）**

- 锐度提示改为**该行之后独立一行**的说明文案，不再与越界/拒绝提示抢同一位置；
  越界与拒绝提示在所有行保持同一列位置。
- 预览容器 `h-44` → `aspect-video`（多数主码流为 16:9，固定高度会留黑边或裁切），
  并补一行元信息：有抓拍时间时显示「预览为设备抓拍的一帧 · {time}」，
  设备离线/无帧时显示 `device.config.previewOffline`。

### 2.3 阶段 2 · 网络字段开放编辑（前端 + 三端契约）

**2.3.1 固件规则表（`firmware/core/src/config.c:293-315`）**

新增 3 条规则，与既有 `net.dhcp` / `net.ip` 并列：

```c
{ "net.mask", CFG_T_STR, 0, 0, NULL, true },
{ "net.gw",   CFG_T_STR, 0, 0, NULL, true },
{ "net.dns",  CFG_T_STR, 0, 0, NULL, true },
```

**不补默认值**：固件对 `register_common_rules` 里的键一律不种子初值（现有 `net.dhcp` / `net.ip` 同样没有），
未设置时 `cfg_get_json` 返回 `HAL_ENODEV`。本轮保持这一现状，不借机写死网关/DNS 这类**产品决策**；
代价是真实设备上这些字段可能读到空值，前端如实显示 `—`（不编造）。

不动 HAL、不动上层逻辑；改完必须跑 CMake 构建与 `tests/hal_conformance`（fail 恒为 0，`AGENTS.md` §4）。

**2.3.2 模拟器与平台**

- `simulator/idp/config.go`：`cfgRules` 增 3 键（`cfgStr`），`cfgDefaults()` 增出厂值
  （`net.mask: "255.255.255.0"`、`net.gw: "192.168.1.1"`、`net.dns: "223.5.5.5"`）。
  **`cfgDefaults` 必须覆盖 `cfgRules` 的全部键**——2.3.3 改完 `supported` 后，
  "有规则但无默认值"的键会直接从界面上消失。
- `platform/server/internal/api/devices.go`：`cfgKeys` 增同 3 键；`cfgRebootRequired` 的
  `net.*` 五项全部为 `true`（对齐固件规则表的 `reboot_required`）。

**2.3.3 修正 `supported` 语义（问题⑪）**

`handleDeviceConfigGet`（`devices.go:591`）当前返回 `"supported": cfgKeys`，即平台白名单。
改为**与设备实际回包求交集**（按 `cfgKeys` 顺序保留交集）：

```go
supported := make([]string, 0, len(cfgKeys))
for _, k := range cfgKeys { if _, has := values[k]; has { supported = append(supported, k) } }
```

**行为变化（有意为之）**：设备没有的键，字段从「显示空值」变为「不渲染」。
这正是阶段 3「不支持区域框选的设备整块不渲染」所依赖的能力。风险在于模拟器若漏了某键的默认值，
该字段会静默消失——因此 2.3.2 要求 `cfgDefaults` 全覆盖。

**2.3.4 前端网络编辑区（`NetworkSettings.vue`）**

以「网络」区块替换现有只读区（`[id].vue:1078-1091`）：

- **DHCP 开启**：只读展示 IP + 说明「地址由 DHCP 分配」；静态四件套输入框禁用。
- **DHCP 关闭**：`ip` / `mask` / `gw` / `dns` 四个输入框可编辑，各自做 IPv4 格式校验。
- 新增 `platform/web/utils/net.ts` 的 `isIPv4(s)`（点分四段、每段 0–255、无前导零歧义），
  非法值走 `UiInput :invalid` + 就地错误文案，**不静默纠正**。
- **独立「保存网络设置」按钮** + 危险确认弹窗（`confirmBox.ask({ danger: true })`），
  说明"保存后设备将重启网络、平台可能短暂失联，且需重启生效"。
- 与通用保存**物理与逻辑都分离**：`saveCfg` 提交时用 `NET_KEYS` 常量过滤掉网络键，
  网络只走自己的保存流程；两者都在 `cfg.data` 里，但**保存范围不同**（这是本轮新增的概念，
  实现时务必只在一处定义 `NET_KEYS`）。

### 2.4 阶段 3 · 移动侦测区域框选（前端 + 三端契约）

**2.4.1 契约：`alarm.motion.regions`**

- **格式**：JSON 文本，元组数组 `[[x, y, w, h], …]`，坐标与尺寸均为**归一化 0–1**，
  **最多 4 个区域**（`profiles/*.json` 的 `ivs.max_regions = 4`；`hal_ivs.h` 上限 8，
  `hal_types.h:113` 的 `hal_rect_t{float x,y,w,h}` 为归一化矩形）。
  对齐 `Docs/PRD/IpcCloud设备接入规范_v1.0.md:308` 的事件 payload 先例。
- **固件无需改动**：规则 `{ "alarm.motion.regions", CFG_T_JSON }` 已存在
  （`firmware/core/src/config.c:311`），`cfg_apply_json` 对非标量走 `json_dump` 后
  `set_value(CFG_T_JSON)`（`:547`），数组会被原样存为 JSON 文本。
- **平台**：`cfgKeys` 增 `alarm.motion.regions`；`cfgRebootRequired` 不含它。
- **模拟器**：`cfgType` 新增 `cfgJSON`；`coerceCfg` 增校验分支——只接受
  元素为「长度 4 的数值数组、每项在 0–1 之间」的数组，且长度 ≤ 4，其余一律拒绝
  （对齐固件"类型不符直接拒绝、不做就地转换"的既有语义）；
  `cfgDefaults` 增 `"alarm.motion.regions": []`。

**2.4.2 `MotionRegionEditor.vue`**

- Props：`modelValue: number[][]`、`maxRegions = 4`、`posterSrc?: string`。
- 画布：`relative` + `aspect-video`；底图为通道抓拍快照；无快照时退化为等比网格背景（**不假装有图**）。
- 叠加层：百分比绝对定位的矩形（`left: x*100%` 等），与底图缩放天然同步，不需要重算像素。
- 交互：空白处按下拖拽=新建；框内拖拽=移动；右下角手柄=缩放；框角 ×=删除。
  坐标钳制在 `[0,1]`，最小尺寸 0.02。归一化值保留 3 位小数，避免浮点噪声写回设备。
- **a11y（必做）**：每个框 `tabindex=0` + `role="group"` + `aria-label`（序号与坐标）；
  `←/→/↑/↓` 微调 0.01（`Shift` 为 0.05）、`Delete` 删除；
  底部区域列表提供等价的删除按钮与「添加区域」（达到上限时禁用并说明）。
- 保存：值挂在 `cfg.data['alarm.motion.regions']`，随 `alarm` 页签的通用「保存并下发」提交
  （不新增独立保存按钮——它不涉及失联风险，与网络字段不同）。
- 渲染条件：`cfg.supported` 不含该键时整块不渲染（依赖 2.3.3）。

### 2.5 决策日志（Decision Log）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | 抽 3 个组件（方案 A） | 全内联 / 整面板抽取 | 三处重复渲染收敛为一处，`[id].vue` 不膨胀；整面板抽取回归面过大 |
| D2 | 依赖禁用字段**不参与**越界校验 | 仍参与校验 | 禁用后用户看不到越界提示，参与校验会复现"看不见的红点 + 保存变灰"，即上一轮问题④ |
| D3 | 脏值用「JSON 快照字符串比较」 | 逐字段 diff / 引入状态库 | 键序稳定、改回原值即不脏；零依赖、实现与验证都简单 |
| D4 | 网络字段独立保存 + danger 确认，且从通用保存中**排除** | 并入通用保存 | 网络改错会导致设备失联，不能与"调亮度"共用一次提交与一次点击 |
| D5 | 固件只加规则、**不补默认值** | 顺便写死网关/DNS 默认值 | 网关/DNS 默认值是产品决策，不该由本轮顺手决定；未设置时前端显示 `—` 更诚实 |
| D6 | `regions` 用元组 `[[x,y,w,h]]` | 对象 `[{x,y,w,h}]` | 接入规范已有该形式的先例（`:308`），且体积更小 |
| D7 | 时区下拉保留表外当前值 | 纯枚举下拉 | 设备可能上报未收录时区，纯枚举会把它显示成空并诱使用户误改 |
| D8 | 区域框选并入 `alarm` 页签的通用保存 | 独立保存按钮 | 区域不涉及失联/重启，独立按钮只会增加"该点哪个保存"的困惑 |

### 2.6 非功能约束

- **i18n**：所有新增文案双写 `locales/zh-CN/device.ts` 与 `locales/en/device.ts`，
  在 `platform/web` 下跑 `python scripts/i18n-check.py` 必须 0 错误（键一一对应、无重复、无死键）。
  模板里一律 `t('字面量')`，不拼键名（脚本只能静态识别字面量）。
- **契约一致性**（`AGENTS.md` §5）：配置键的键名/类型/范围在固件规则表、模拟器 `cfgRules`、
  平台 `cfgKeys` 三处逐字对齐；每加一键必须实测一次读写闭环，不能只靠走读。
- **不假成功、不静默钳制**：越界值保持可见错误态；按钮点击必须产生真实效果或处于明确禁用态并说明原因。
- **权限**：本轮不新增 API 端点，权限层级不变（网络与区域复用 `PUT /devices/:id/config`）。
- **规模**：单设备配置键约 32 个；区域 ≤ 4 个；无服务端性能影响（一次 `cfg.set` 往返）。
- **安全**：网络字段（IP/掩码/网关/DNS）只做格式校验，不做网段推断；强确认文案明确"可能导致失联"。
- **无自动化测试套件**：`platform/CLAUDE.md` 已注明，验证依赖手工闭环 + 构建/静态检查。

|---|---|---|

### 2.8 风险与回滚点

1. **依赖禁用 × 校验的交互**（D2）是新增规则，写错会静默漏校验（比"过度拦截"更隐蔽）。
   回滚点：禁用字段一律不进 `invalidKeysByTab` 之外，再加一份"禁用状态下的字段清单"断言便于自测。
2. **离开确认可能"卡住导航"**：若 `confirmBox` 在组件卸载后不 resolve，导航会永久挂起。
   回滚点：先只上 `beforeunload` + 页内子页签切换拦截，`onBeforeRouteLeave` 若不稳定可退。
3. **`supported` 改交集后字段会消失**（2.3.3）——必须确保模拟器 `cfgDefaults` 覆盖全部 `cfgRules` 键，
   否则界面会缺字段却不报错。回滚点：改回"返回 `cfgKeys`"，仅在前端用 `values` 判空兜底。
4. **固件规则表改动**需构建 + `hal_conformance` 双验证；`AGENTS.md` §4 的 CMake 门禁不可绕过。
5. **区域框选是纯新组件**：pointer 事件在触屏上的 `pointercapture` 行为与键盘路径要分别测。
   回滚点：去掉缩放手柄，只保留"新建 / 移动 / 删除"。
6. **`NET_KEYS` 保存范围**是本轮新增概念，漏改一处会出现"看起来保存了但没下发"。
   回滚点：把"哪些键归通用保存"收敛为单一常量 + 一个 `nonNetData()` 函数，禁止各处自行过滤。

## 三、验证方式

1. **构建与静态检查**：`cd platform/web && npm run build`；`python scripts/i18n-check.py`
   （注意：`npm run build` 不含类型检查，"类型错误只能靠浏览器联调发现"）。
2. **后端**：`cd platform/server && go build ./... && go vet ./internal/... && go test ./...`。
3. **模拟器**：`cd simulator && go build ./...`。
4. **固件**（阶段 2 改规则表后）：CMake 配置 + 构建 + `ctest`，`tests/hal_conformance` fail 必须为 0。
5. **联调**：`:3000` 是 compose 的生产构建，**源码改动必须 `cd platform && docker compose up -d --build web`**
   才可见（同目录 nuxt dev 在 `:3010` 且登录不上，不要在那验证）。
6. **手工用例**（必须实际走一遍并记录所见）：
   - 依赖禁用：关「启用录像」→ 录像模式/保留天数/通道变灰且有原因；关「启用侦测」→ 灵敏度同理。
   - 交叉校验：在「编码策略」填越界码率 → 只在编码策略亮红点、保存变灰；切到「移动侦测」保存不受影响；
     再把「启用侦测」关掉，确认灵敏度变灰后**不再**计入越界。
   - 脏值：不动任何字段时保存按钮禁用；改一个值后出现「有未保存的修改」；点「重新回读」弹确认；
     切子页签/返回/刷新各有一次拦截。
   - 回读反馈：保存后出现「已下发，正在回读设备…」，5 秒后表单刷新。
   - 时区：下拉可选且有当前值；保存后再回读，值不变。
   - 网络：DHCP 开关切换后静态四件套启用/禁用；填 `192.168.1.999` 立刻报错；保存弹危险确认；
     `PUT` 只带网络键（不带亮度等），且通用保存只带非网络键。
   - `supported`：故意从模拟器 `cfgRules` 移除一键，确认该字段从界面消失而非显示空值。
   - 区域框选：拖拽新建 4 个区域后「添加区域」禁用；越界拖拽被钳制在画布内；
     键盘微调与 Delete 生效；保存后回读，区域与坐标一致；
     非 IDP 设备 / 不支持该键的设备整块不渲染。
